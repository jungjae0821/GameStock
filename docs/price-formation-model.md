# 뉴스·거래 기반 가격 형성 모델

이 문서는 GameStock의 현재 구현을 고정된 기준으로 설명한다. GameStock은 실제 금융상품의 가격을 예측하지 않고, 게임 뉴스와 참여자의 주문이 가상 시장에서 어떻게 가격으로 이어지는지 관찰하는 시뮬레이션이다.

## 1. 모델의 입력과 역할

| 입력 | 수치화 방식 | 가격에 미치는 역할 |
| --- | --- | --- |
| 뉴스 영향도 | 뉴스 감성 분석 결과 `-10..+10` | 최근 24시간 뉴스가 봇의 기준 호가를 어느 방향으로 이동할지 결정 |
| 뉴스 최신성 | `r = clamp(1 - 경과시간/24시간, 0, 1)` | 오래된 뉴스일수록 영향이 선형으로 감소 |
| 이용자 체결량 | 최근 24시간 매수·매도 체결 수량 | 실제 주문이 호가를 소진하고 체결 가격·VWAP를 만드는 수요·공급 |
| 봇 체결량 | 최근 24시간 봇 매수·매도 체결 수량 | 유동성을 공급하고, 봇 가격 이동 상한 안에서 체결을 만들어 냄 |
| 호가 잔량·불균형 | 현재 공개된 매수·매도 잔량 | 다음 체결 가능 가격과 시장가 슬리피지에 간접 반영 |
| 최근 가격 모멘텀 | `current_price`와 `previous_price`의 차이 | 별도 가중치로 가격을 덮어쓰지 않고 변동률·설명 문구의 기준으로 사용 |

현재 모델은 뉴스·거래량·호가를 단순히 고정 비율로 더하는 점수식이 아니다. 뉴스는 봇 호가의 기준을 정하고, 이용자·봇 주문은 가격·시간 우선 매칭을 통해 실제 체결가를 만든다. 거래량과 호가 불균형은 체결 가능성과 VWAP에 영향을 주므로 최종 가격에 간접적으로 반영된다. `/api/stocks/{stockCode}/price-drivers`는 이 과정을 같은 원장 데이터에서 계산해 공개한다.

## 2. 뉴스 영향 계산

각 뉴스 `i`의 영향도 `I_i`와 최신성 `r_i`를 사용한다.

```text
I_i = 뉴스 영향도 (-10 .. +10)
r_i = clamp(1 - 경과시간 / 24시간, 0, 1)
```

뉴스 한 건에 적용하는 최대 비율 `L_i`는 다음과 같다.

| 조건 | `L_i` |
| --- | ---: |
| 일반 뉴스 | 2% |
| 특별 뉴스: `abs(I_i) >= 6` | 5% |
| 매우 큰 사건·사고: `I_i <= -8`이고 사건·사고 문맥이 확인됨 | 10% |

한 건의 실제 기준 호가 영향은 다음과 같이 최신성과 영향도 크기를 함께 반영한다.

```text
n_i = sign(I_i) × L_i × (abs(I_i) / 10) × r_i
```

최근 24시간 뉴스의 합은 특별 뉴스가 없으면 ±5%, 특별 뉴스가 하나라도 있으면 ±10%로 다시 제한한다.

```text
N24 = clamp(sum(n_i), -aggregateLimit, +aggregateLimit)
aggregateLimit = 5%  (일반)
aggregateLimit = 10% (특별 뉴스 포함)
```

영향도 0인 뉴스는 가격 방향을 만들지 않는다. 뉴스 영향은 현재가에 직접 적용되지 않고 봇의 기준 호가 계산에만 사용된다.

## 3. 봇 틱과 최종 현재가

봇 시뮬레이션은 5초마다 실행된다.

1. `simulation_state.tick`을 1 증가시킨다.
2. `GAMESTOCK_SIMULATION_SEED`와 틱 번호로 난수열을 만든다.
   `seed ^ (tick × 0x9E3779B97F4A7C15L)`
3. 고정된 종목 ID 순서에서 종목 하나를 선택하고 최근 24시간 `N24`를 계산한다.
4. 현재가 `P`에서 뉴스 기준가를 만든다.

   ```text
   fairPrice = P × (1 + N24)
   ```

5. 봇 지정가를 기준가의 양옆에 배치한다. 오프셋은 0.2% 이상 0.8% 미만의 재현 가능한 난수이며, 매수가는 호가 단위 내림, 매도가는 호가 단위 올림을 적용한다. 한 번의 지정가 수량은 5~30주다.
6. 봇 시장가 주문을 양쪽에 각각 3~24주 생성하고, 가격·시간 우선으로 일부 호가를 소비한다. 한 틱 안에서도 매수·매도 순서는 시드 난수로 섞인다.
7. 실제 체결이 발생하면 체결 금액의 가중평균인 VWAP를 계산한다.
8. 봇 틱에서 현재가가 이동할 수 있는 최대 폭을 적용한다.

   ```text
   normalStep  = ±0.5% of 체결 직전 현재가
   specialStep = ±1.0% of 체결 직전 현재가
   P_next = clamp(VWAP, P - maxStep, P + maxStep)
   maxStep = max(호가 단위, round(P × stepRate))
   ```

   특별 뉴스가 있으면 `specialStep`을 사용한다. 체결이 없으면 현재가는 변경되지 않는다.

이 순서 때문에 뉴스가 매우 강해도 봇 한 틱에서 현재가가 바로 10% 이동하지 않는다. 뉴스의 ±5%·±10% 한도는 봇이 제출하는 기준 호가의 영향 범위이고, 최종 현재가의 틱별 이동은 별도의 ±0.5%·±1% 체결 상한을 따른다. 여러 틱에 걸친 누적 변화는 실제 체결이 계속 발생할 때만 나타난다.

## 4. 이용자 주문과 체결가

- 시장가 주문은 반대편 최우선 호가부터 소진한다.
- 지정가 주문은 가격 우선, 같은 가격에서는 시간 우선으로 매칭한다.
- 부분 체결 후 남은 시장가 수량은 즉시 취소한다.
- 체결가가 발생하면 해당 주문의 실제 체결가를 사용해 현재가와 가격 이력을 갱신한다.
- 체결 수수료는 매수·매도 각각 거래대금의 0.10%이며, 체결·현금·주식 반영은 하나의 트랜잭션에서 처리한다.

따라서 이용자 거래에는 별도의 임의 변동률을 곱하지 않는다. 이용자 주문이 어떤 호가를 실제로 체결했는지와 체결 수량이 최종 가격을 결정한다.

## 5. 계산 예시

### 일반 뉴스 예시

현재가가 10,000원이고 최근 24시간 뉴스가 다음과 같다고 가정한다.

| 뉴스 | 영향도 | 경과시간 | 최신성 | 계산 결과 |
| --- | ---: | ---: | ---: | ---: |
| 업데이트 흥행 | +4 | 0시간 | 1.00 | `+2% × 0.4 × 1 = +0.8%` |
| 이용자 이탈 우려 | -2 | 12시간 | 0.50 | `-2% × 0.2 × 0.5 = -0.2%` |

```text
N24 = +0.8% - 0.2% = +0.6%
fairPrice = 10,000 × 1.006 = 10,060원
```

봇 호가가 10,040원과 10,080원에 놓이고 실제 체결 VWAP가 10,070원이라면, 일반 틱 상한 ±0.5%에 따라 다음 현재가는 최대 10,050원까지만 이동한다. 나머지 차이는 다음 체결에서 이어진다.

### 특별 뉴스 예시

영향도 `+8`인 특별 뉴스가 방금 등록되면 한 건의 기준 호가 영향은 `+5% × 0.8 = +4%`다. 최근 24시간 누적 한도는 특별 뉴스가 포함되므로 ±10%가 적용된다. 그래도 해당 틱의 실제 현재가 이동은 특별 봇 틱 상한인 ±1%를 넘지 않는다.

### 매우 큰 사건·사고 예시

영향도 `-9`이고 사건·사고 문맥이 확인된 뉴스는 한 건 최대 10% 범위를 사용한다. 최신성이 1이면 기준 호가 영향은 `-10% × 0.9 = -9%`지만, 체결이 없으면 현재가는 그대로이고, 체결이 발생해도 해당 봇 틱에서는 최대 -1%까지만 이동한다.

## 6. 가격 변동 이유와 기대 지수

`/api/stocks/{stockCode}/price-drivers`는 최근 24시간의 다음 값을 제공한다.

- `newsImpact`: 최신성 가중치를 적용한 뉴스 영향도 합계. 설명용으로 -10..+10으로 제한한다.
- `userBuyVolume`, `userSellVolume`: 이용자 체결량
- `botBuyVolume`, `botSellVolume`: 봇 체결량
- `openBuyVolume`, `openSellVolume`: 현재 미체결 호가 잔량
- `currentPrice`, `previousPrice`, `changePercent`: 현재 가격 흐름
- `reason`: 뉴스 방향과 매수·매도 흐름을 함께 비교한 자연어 설명

화면은 내부 봇 수치나 영향도 숫자를 사용자에게 강제로 노출하지 않고, 뉴스·거래·호가 근거와 “매수세가 우세해 가격이 상승했습니다”와 같은 설명으로 보여준다. 이 API의 수치는 가격을 다시 계산하는 별도 모델이 아니라, 실제 원장과 현재 가격을 설명하기 위한 공개 지표다.

## 7. 재현 절차

재현에는 코드 버전, DB 스냅샷, 시드, 시작 틱을 함께 고정해야 한다.

1. MySQL `gamestock` 데이터베이스에서 `stocks`, `market_events`, `orders`, `portfolios`, `simulation_state`를 스냅샷한다. 서비스 계정·비밀번호는 스냅샷이나 저장소에 포함하지 않는다.
2. 뉴스가 바뀌지 않도록 테스트 환경의 `.env`에서 다음을 사용한다.

   ```text
   GAMESTOCK_NEWS_ENABLED=false
   GAMESTOCK_SIMULATION_SEED=20260910
   ```

3. 스냅샷을 복원하고 `simulation_state.tick`을 동일한 시작 값으로 맞춘다. 기존 봇 미체결 주문과 봇 보유 수량도 포함되어야 한다.
4. 같은 애플리케이션 빌드로 서버를 시작하고, 틱 실행 전후에 다음 API를 저장한다.

   ```text
   GET /api/stocks
   GET /api/stocks/{stockCode}/price-drivers
   GET /api/stocks/{stockCode}/orderbook
   GET /api/stocks/{stockCode}/trades
   ```

5. 동일한 틱 번호에서 종목 선택, 주문 방향·수량, 체결 수량·가격, VWAP, 다음 현재가가 일치하는지 비교한다. 뉴스 수집을 다시 켜면 외부 RSS와 현재 시각이 달라지므로 동일 결과를 보장하지 않는다.

기본 시드는 `20260910`이며 `backend/src/main/resources/application.yml`의 `gamestock.simulation.seed`로 설정된다. 재현 결과는 뉴스 원문·게시 시각, 시작 가격·호가·봇 잔고, 틱 번호를 함께 기록해야 검증할 수 있다.
