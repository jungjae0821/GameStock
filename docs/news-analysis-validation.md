# 뉴스 필터·감성 분석 검증

GameStock 뉴스 수집은 RSS 검색 결과를 그대로 종목 뉴스로 사용하지 않는다. `NewsRelevance`가 종목 별칭과 게임 문맥을 함께 확인하고, 통과한 제목·본문에 `NewsFeedService`의 설명 가능한 키워드 점수를 적용한다.

## 관련성 규칙

1. 종목 별칭이 제목·본문·출처에 하나 이상 있어야 한다.
2. `게임`, `업데이트`, `출시`, `패치`, `캐릭터`, `서버`, `유저` 같은 공통 게임 문맥 또는 종목별 문맥이 있어야 한다.
3. 해킹·개인정보 유출·서버 장애·환불·논란·소송 같은 사건·사고 문맥은 일반 게임 단어가 없어도 종목 별칭과 함께 있으면 통과한다.
4. 정치·부동산·스포츠·보드게임·일반 주식 등 명시적인 비게임 문맥이 있으면 제외한다. 단, 게임 매체의 짧은 기사라도 비게임 문맥이 동시에 있으면 구제하지 않는다.
5. 종목별 API는 게시 시각 최신순으로 후보를 읽고, 관련성·원문 출처 기준 중복 제거 후 최대 5건만 반환한다. 시장 전체 이벤트는 같은 방식으로 최대 10건을 반환한다.

사건·사고 문맥 목록은 가격 모델의 매우 큰 사건 판정에도 공유된다. 따라서 뉴스 필터와 가격 충격 규칙이 서로 다른 단어 사전을 사용하지 않는다.

## 감성 점수 규칙

- 긍정·부정 키워드에는 1~4의 가중치를 둔다. 서비스 종료·개인정보 유출·해킹처럼 위험이 큰 표현일수록 높게 둔다.
- 제목 적중은 본문 적중의 2배로 계산한다.
- 부정 표현을 먼저 점수화하고 해당 구문을 제거한 뒤 긍정 표현을 계산한다. `출시 취소`처럼 긴 부정 구문이 `출시`라는 긍정 단어로 다시 계산되지 않게 하기 위한 순서다.
- 같은 구문은 제목·본문에서 각각 최대 2회까지만 계산한다.
- 최종 점수는 `긍정 점수 - 부정 점수`를 `-10..+10`으로 제한한다. 0은 양쪽 신호가 없거나 서로 상쇄된 중립이다.

예를 들어 제목의 `대규모 업데이트`(가중치 3)는 `3 × 2 = 6`점, 본문의 `흥행`(가중치 2)은 2점으로 계산된다. 반대로 제목의 `개인정보 유출`(가중치 4)은 -8점이다.

## 손으로 분류한 검증 표본

`backend/src/test/java/com/gamestock/backend/market/NewsAnalysisTest.java`에 다음 표본을 고정해 둔다. `정답 방향`은 사람이 제목·요약을 읽고 부여한 라벨이며, 테스트는 실제 분류기의 방향(긍정·부정·중립)이 일치하는지 확인한다.

| 표본 | 관련성 | 정답 방향 | 검증 포인트 |
| --- | --- | --- | --- |
| 우마무스메 대규모 업데이트 흥행 | 관련 | 긍정 | 제목의 복합 긍정 신호 |
| 블루 아카이브 서버 장애 논란 | 관련 | 부정 | 사건·사고 문맥 |
| 니케 개인정보 유출 사건사고 | 관련 | 부정 | 매우 큰 사건 후보 |
| 우마무스메 신규 소식 | 관련 | 중립 | 방향 키워드 없음 |
| 블루 아카이브 출시 취소 | 관련 | 부정 | 긴 부정 구문 우선 처리 |
| 우마무스메 경마 경기 결과 | 제외 | 해당 없음 | 종목명만으로는 부족 |

현재 표본은 규칙 회귀 방지용 소규모 고정 세트다. 정확도 수치를 일반 뉴스 전체의 성능으로 해석하지 않으며, 실제 RSS에서 수집한 표본을 추가할 때는 사람이 먼저 라벨을 확정하고 관련성·감성 정확도를 각각 계산한다.

## 시장 신호와의 비교

`/api/stocks/{stockCode}/price-drivers`는 같은 기간의 뉴스 영향도, 이용자·봇 매수·매도 체결량, 미체결 호가 잔량, 현재가와 이전 가격을 함께 반환한다. 분석 시 다음을 종목별·기간별로 저장한다.

- 뉴스: 게시 시각, 영향도, 최신성 가중 합계
- 거래: 매수·매도 수량, 총 체결량, VWAP
- 호가: 매수·매도 잔량과 스프레드
- 결과: 기간 시작·종료 가격, 변동률, API의 `reason`

뉴스와 가격 방향이 다르면 오탐으로 단정하지 않고 `매수세가 뉴스 방향을 상쇄`, `호가 부족으로 슬리피지 발생`, `뉴스가 24시간 창에서 만료` 같은 원인을 기록한다. 이 기록은 가격 설명 문구가 실제 원장과 어긋나는 사례를 찾는 데 사용한다.

## RSS 운영·출처

- RSS 원문은 제목·요약·게시 시각·출처 링크만 저장하고, 본문 전체를 복제하지 않는다.
- 저장된 설명에는 원문 출처 URL을 붙여 화면에서 원문으로 이동할 수 있게 한다.
- 제목과 출처 URL을 기준으로 중복을 제거한다.
- 게시 시각이 없는 항목은 생성 시각을 보조 기준으로 사용하며, 최근순 정렬에서 뒤로 보낸다.
- 수집 실패·비정상 HTTP 응답·파싱 실패는 로그에 남기고 기존 시장 API와 거래는 계속 제공한다.
- 외부 RSS의 이용 약관과 재배포 조건은 배포 전 피드별로 확인한다. GameStock은 뉴스 원문을 재배포하지 않고 링크와 짧은 요약만 제공한다.

실행 방법은 `mvn test`이며, 현재 고정 표본 테스트는 관련성·사건 문맥·긍정/부정/중립 방향·점수 상한을 검증한다.
