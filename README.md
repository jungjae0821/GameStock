# 슈엔증권 (GameStock)

**내가 좋아하는 게임에 투자해 그 게임의 값을 올리는 모의 주식 게임.**

서브컬처 게임 20종을 가상 주식 종목으로 상장했습니다. 사용자는 모의 자금 100만원으로 게임 주식과 ETF·선물·옵션을 사고팔고, 실제 게임 뉴스와 게임사 공식 발표, 다른 투자자들의 주문이 가격을 움직이는 과정을 실시간으로 지켜봅니다. 종목마다 토론방과 채팅방이 있고, 직접 만든 퀀트 전략으로 자동 매매도 할 수 있습니다. 서비스 이름은 **슈엔증권**, 저장소와 백엔드 프로젝트 이름은 **GameStock**입니다.

- 웹: https://gamestock-20994.web.app
- API: https://gamestock-api.161-33-33-45.sslip.io (상태 확인 `/api/health`, 준비 상태 `/api/health/ready`)
- 모바일: Expo(React Native) 앱, Android·iOS 대상

> 모의 투자 서비스입니다. 실제 주식·현금·게임 재화를 거래하지 않으며, 화면의 모든 금액은 가상 자금입니다.

## 만든 의도

서브컬처 게임 팬들은 자기가 하는 게임에 대한 애정이 큽니다. 커뮤니티에서는 "우리 게임이 더 잘나간다"는 이야기로 자주 경쟁이 붙습니다. 슈엔증권은 그 경쟁을 **주식 시장**으로 옮겨 왔습니다.

- **내 게임을 사서 값을 올린다.** 좋아하는 게임의 주식을 많은 사람이 사면 실제 매수 주문이 호가를 소화하면서 가격이 오릅니다. 팬덤의 응원이 숫자로 보입니다.
- **게임끼리 경쟁이 붙는다.** 홈 화면의 시장 지도와 "오늘 많이 움직인 종목"에서 어떤 게임이 오르고 내리는지 바로 비교할 수 있습니다. 대형 업데이트나 논란 같은 실제 뉴스, 게임사의 공식 공지도 가격에 반영됩니다.
- **투자 실력도 겨룬다.** 순자산 랭킹과 주간 수익률 랭킹, 칭호가 있어서 "어떤 게임을 언제 샀는가"로 다른 사용자와 겨룹니다.
- **같은 종목 팬끼리 이야기한다.** 종목마다 토론 게시판과 실시간 채팅방이 있고, 홈 화면 위 전광판에 한 줄 메시지를 사서 올릴 수 있습니다.
- **시장이 어떻게 움직이는지 배운다.** 가격은 난수가 아니라 호가와 체결로 정해집니다. 뉴스 → 주문 → 호가 → 체결 → 가격으로 이어지는 흐름을 직접 관찰하고, 지표와 퀀트 전략으로 시험해 볼 수 있습니다.
- **보상 체계** 실제 금전같은걸 걸수는 없으니 게임 이용 시 제공되는 칭호로 수집욕구를 자극시키려는 의도가 있습니다.

사람이 적은 시간에도 시장이 비어 보이지 않도록, 서버에서 6,020명 규모의 전략 봇, 유동성 공급 봇, 48개의 선물·옵션 봇이 사람과 같은 규칙으로 거래합니다. 봇은 가격을 정해 주는 장치가 아니라, 사람과 같은 규칙으로 주문을 내는 시장 참여자입니다. 자세한 내용은 [봇의 역할](#봇의-역할)에 있습니다.

## 핵심 흐름 한눈에 보기

```text
 실제 게임 뉴스(RSS)·공식 발표          사람의 주문 (웹·앱·자동 주문·퀀트 전략)
        │                                   │
        ▼                                   ▼
 관련성 필터 → 영향 점수(-10~+10)     주문 접수·검증 (잔고·가격제한·VI)
        │                                   │
        ▼                                   ▼
 종목 내재가치·합의가치 갱신 ──▶ 봇 판단 ──▶ 같은 호가창에서 가격·시간 우선 매칭
                    ▲                       │
 선물·옵션 쏠림 압력 ┘                       ▼
                               체결 → DB 커밋 → 현재가 변경
                                            │
                                            ▼
                     WebSocket으로 시세·호가·체결·내 계좌 전송 (웹·앱)
```

**현재가는 실제 체결로만 바뀝니다.** 뉴스나 봇, 파생 포지션이 가격을 직접 써넣지 않습니다. 뉴스와 파생 쏠림은 봇이 생각하는 적정 가치와 주문 방향을 바꾸고, 그 생각이 주문이 되고, 주문이 체결될 때 비로소 가격이 움직입니다.

## 시스템 구조

```text
┌──────────── 웹 (React) ─────────────┐   ┌──────── 모바일 (Expo) ────────┐
│ Firebase 로그인 → ID 토큰            │   │ 네이티브 탭 · 앱 안 Google 로그인│
└──────┬──────────────┬───────────────┘   └──────┬──────────────┬─────────┘
       │ REST /api/*   │ WebSocket /ws/stream       │ REST          │ WebSocket
       └───────────────┴──────────────┬─────────────┴───────────────┘
                                      ▼
                 Nginx (HTTPS·WSS) ─▶ Spring Boot (OCI VM, 127.0.0.1:8081)
                 ├─ 주문 접수 → 메모리 호가 매칭 → 배치 DB 저장 (영수증으로 중복 방지)
                 ├─ 봇 스케줄러: 4개 종목 그룹, 접속자 있을 때만 상시 매칭
                 ├─ 선물·옵션 봇, 파생 쏠림 → 현물 주문 압력
                 ├─ 거래 보호: 가격제한폭 · VI · 서킷브레이커 · 단일가
                 ├─ 뉴스 수집(10분) · 공식 발표 수집(6시간) · 본문 발췌 · 영향 분석
                 ├─ 손절·익절 자동 주문(1초), 퀀트 전략 실행(2초)
                 ├─ 대출 이자·담보 감시, 주간 랭킹·칭호, 미션, 출석, 전광판
                 ├─ 일별 순자산 기록, 토론·채팅, 프로필 사진
                 ├─ 공개 시세 캐시 (변경 시에만 DB 재조회)
                 ├─ DB 끊김 후 매칭 소유권 자동 복구(2초)
                 └─ 오래된 데이터 정리 (무료 DB 용량 유지)
                                      │ TLS, 사설망
                                      ▼
                          MySQL (OCI, gamestock 스키마)

 별도 감시 서버 ── 30초마다 웹·/api/health·/api/health/ready·/ws/market·/ws/stream 확인 ──▶ Discord
```

- 웹과 앱은 같은 백엔드, 같은 실시간 스트림, 같은 Firebase 인증을 사용합니다.
- 로그인하지 않아도 시장·종목·뉴스·랭킹·토론을 볼 수 있습니다. 주문, 계좌, 글쓰기, 퀀트 화면에는 로그인이 필요합니다.
- 실시간 연결이 끊기면 웹은 지수 백오프(최대 15초)로 재연결하고, 연결 상태를 확인하는 하트비트와 4분마다 인증 갱신을 보냅니다.

## 화면별 설명

### 웹

웹은 해외 거래소 스타일의 다크 테마가 기본이며 라이트로 바꿀 수 있습니다. 휴대폰 폭에서도 쓸 수 있도록 반응형으로 구성했습니다. 상단에는 종목별 현재가가 흐르는 시세 띠가 있습니다. 데스크톱 상단 메뉴에는 8개 항목이 있고, 휴대폰 폭에서는 하단 탭 6개(퀀트·API는 계정 메뉴로 이동)로 바뀝니다.

## 기능이 돌아가는 원리

### 1. 주문과 매칭

1. 주문이 들어오면 서버가 종목·수량(1~1,000주)·주문 유형을 검증하고, 거래 보호 상태(VI·서킷브레이커·거래 정지)를 확인합니다.
2. 사람 주문은 전용 접수 큐에 쌓이고, 2ms 동안 모인 주문을 최대 200건까지 한 트랜잭션으로 처리합니다. 봇 주문보다 먼저 처리됩니다.
3. 매칭은 **가격 우선, 같은 가격이면 시간 우선**입니다. 매수 지정가는 그 가격 이하의 매도 호가와, 시장가는 실행 범위(기준가 ±10%) 안의 가장 좋은 호가와 체결됩니다. 체결되지 않은 지정가 수량은 호가창에 남습니다.
4. 매수 주문은 필요한 현금을 **예약**하고, 매도 주문은 보유 수량을 예약합니다. 미체결 주문을 취소하면 예약이 풀립니다. 그래서 같은 돈이나 주식을 두 번 쓸 수 없습니다.
5. 체결 결과는 **DB에 커밋된 뒤에만** 성공으로 응답합니다. 주문 배치마다 영수증을 함께 저장해서, 커밋 응답이 유실돼 다시 시도하더라도 주문이 두 번 실행되지 않습니다.

### 2. 자동 매도 (손절·익절)

- 보유 종목에 손절가(이하로 떨어지면) 또는 익절가(이상으로 오르면)를 걸어 둘 수 있습니다. 계정당 활성 주문은 최대 10개입니다.
- 서버가 1초마다 현재가를 확인하고, 조건을 넘으면 **일반 주문 경로로 시장가 매도**를 냅니다. 다른 주문에 묶이지 않은 보유 수량만 팔고, 보유가 0이 되면 같은 종목의 나머지 자동 주문을 닫습니다.
- API는 `/api/stop-orders`이고, 계좌를 초기화하면 함께 지워집니다.

### 3. 가격이 정해지는 방식

- 현재가는 **마지막 체결가**입니다. 체결이 없으면 가격도 그대로입니다.
- 각 종목에는 실제 게임 이용자 규모를 본뜬 가상 규모(시가총액·유동성)가 있습니다. 대형주 8개는 천천히, 소형주 12개는 크게 움직입니다. 이 수치는 시뮬레이션 입력값이며 실측 통계가 아닙니다.
- 종목별 상장가는 100원(KD)부터 215,000원(GI)까지 다릅니다. 동전주도 오르내릴 수 있도록 최저 가격과 호가 단위는 1원입니다.
- 봇은 **합의 가치**(시장 참여자들이 생각하는 적정가) 주변에서 호가를 냅니다. 합의 가치는 종목 규모에 맞춘 무작위 걸음으로 조금씩 움직이고, 시장 국면을 따라 흐르며, 뉴스가 바꾼 목표가 쪽으로 수십 분에 걸쳐 끌려갑니다. 뉴스가 나오자마자 가격이 순간이동하지 않는 이유입니다.
- 선물·옵션 포지션이 한쪽으로 쏠리면 현물 봇의 주문 방향에 약한 압력이 더해집니다. 예를 들어 숏이 몰린 상태에서 지수가 오르면 환매수 압력이 생깁니다. 압력은 ±0.85로 제한되고 시간이 지나면 사라지며, 실제로 체결이 일어나야만 가격이 바뀝니다.
- 게임주 지수는 전 종목을 시가총액 비중으로 담은 지수 ETF(`ETFIDX`)의 NAV입니다. 처음 1000에서 시작했고, 자정에 다시 1000으로 돌아가지 않고 전날 종가에서 이어집니다. 등락률은 전날 종가 대비이고, 선물·옵션도 이 지수를 따릅니다. 새 종목은 실제 체결 기준가가 검증된 뒤에 바스켓에 편입되며, 편입할 때 보유 가치와 전일 기준을 보존합니다.

### 4. 가격 단위 환산 (2026-10-27)

5개 종목을 추가하면서 기존 15개 종목의 주당 가격을 종목별 상장가로 바꿨습니다. 환산은 새 버전이 처음 시작할 때 한 번만, 한 트랜잭션으로 실행됩니다(`StockDenominationMigration`).

- 기존 평가가 `M`, 새 기준가 `N`일 때 보유 `q`주는 `floor(q×M/N)`주가 되고, 남는 금액은 수수료 없이 현금으로 지급합니다. 1주 미만이면 전량 현금 정산합니다.
- 해당 종목의 미체결 주문은 취소하고 예약을 풉니다. 가격 이력·뉴스 기준가·ETF 구성 단위도 함께 환산하고, 계좌 자산과 ETF 가치 검증이 실패하면 전부 되돌립니다.
- 환산 기준과 계좌별 전후 기록은 `stock_denominations`, `stock_denomination_positions`, `stock_denomination_orders`에 남습니다. 원래 체결·정산 원장은 그대로 보존합니다.

### 5. 뉴스와 공식 발표 분석

1. **수집**: 10분마다 종목별 Google 뉴스 RSS를 가져옵니다(게임 이름으로 검색 주소를 자동 생성). 원작과 파생작(예: 카트라이더와 카트라이더: 드리프트)은 따로 판별해서 한 기사가 엉뚱한 종목에 중복 반영되지 않게 합니다.
2. **공식 발표**: 6시간마다 게임사 공식 채널의 공지를 가져옵니다. 관련성 필터를 건너뛰고, 같은 제목의 언론 기사보다 1.5배 가중치를 줍니다. 처음 수집할 때 발견한 예전 글은 목록에만 올리고 가격에는 반영하지 않습니다. 글은 원문 링크 기준으로 식별해서 제목이 고쳐지면 같은 글을 갱신합니다.

   | 종목 | 출처                       | 읽는 방식                                   |
   | ---- | -------------------------- | ------------------------------------------- |
   | GOV  | 니케 공식 사이트 공지 탭   | 사이트 커뮤니티 JSON API                    |
   | UMA  | 우마무스메 공식 다음 카페  | 공지사항·업데이트 게시판의 모바일 페이지    |
   | BA   | 블루 아카이브 넥슨 포럼    | 공지사항·업데이트 게시판의 공개 JSON API    |

3. **관련성 필터**: 제목·본문이 그 게임에 관한 기사인지 규칙으로 판별하고, 같은 기사의 중복 게재를 하나로 묶습니다.
4. **영향 점수**: 가중 키워드 규칙으로 -10~+10 점수를 매깁니다. 대규모 업데이트·흥행·매출 증가는 양수, 서비스 장애·논란·소송은 음수입니다. 생성형 AI나 학습된 예측 모델은 쓰지 않습니다.
5. **본문 발췌**: 원문 주소를 풀어 기사 첫 문단을 미리 저장해 둡니다. 인사말 같은 의미 없는 첫 줄은 건너뜁니다.
6. **가격에 미치는 경로**: 최근 24시간 안의 관련 뉴스 10건이 시간이 지날수록 약해지는 가중치로 합산됩니다. 이 값이 종목의 내재가치와 합의 가치 목표를 움직이고, 뉴스 반응형 봇은 각자의 반응 지연 시간이 지난 뒤 주문을 냅니다.

뉴스 화면의 "발행 이후 가격 변화"는 다른 거래와 시장 요인도 포함한 값입니다. 그 기사 하나의 효과만 뜻하지 않습니다.

### 7. 실시간 전송

- 서버는 종목별로 직렬화한 스냅샷 하나를 만들어, 그 종목을 구독한 모든 연결에 같은 메시지를 보냅니다. 연결 수가 늘어도 종목당 계산은 한 번입니다.
- 내 계좌(잔고·보유·주문 상태)는 로그인한 연결에만 개인 채널로 보냅니다. 보유 종목 평가액은 2초마다 다시 계산하고, 바뀐 경우에만 보냅니다.
- 첫 화면이 기다리는 공개 시세·시장 상태·뉴스는 서버가 미리 계산해 둡니다. 체결이나 정비가 커밋됐을 때만 DB를 다시 읽고, 뉴스는 수집·발췌가 저장됐을 때만 다시 읽습니다.
- 차트 지표는 브라우저·앱이 이미 받은 캔들로 직접 계산합니다. 그래서 진행 중인 캔들과 함께 움직입니다. 공식은 서버의 `TechnicalIndicators`와 같습니다.
- 종목 채팅은 WebSocket이 아니라 약 2초 간격의 커서 폴링으로 새 메시지를 받습니다.

### 8. 접속에 따라 바뀌는 시장 속도

- 웹·앱 접속(WebSocket 연결 또는 API 요청)이 있으면 **활성 모드**입니다. 4개 종목 그룹이 250ms 간격으로 봇 매칭을 돌리고, 종목당 초당 체결 목표에 맞춰 주문량을 정합니다.
- 마지막 접속 후 2분이 지나면 **유휴 모드**로 내려갑니다. 30분마다 짧은 매칭(배치 5회)만 하고, 쉬는 동안 밀린 체결을 나중에 몰아서 만들지 않습니다.
- 상태 확인(`/api/health`, `/api/health/ready`)과 봇 자신의 활동은 접속으로 치지 않습니다.

### 9. 정산과 계좌

- 체결 즉시 정산됩니다. 매수자는 주식을, 매도자는 대금을 바로 받습니다.
- 사람이 참여한 체결에는 매수·매도 각각 0.1% 수수료가 붙습니다.
- 총자산 = 현금 + 주문에 묶인 예약 현금 + 보유 종목 평가액 + ETF·파생 평가액 − 대출 잔액. 평가액은 최근 체결 흐름과 호가로 계산한 평가 가격(mark price)을 씁니다. 한 번의 튀는 체결로 자산이 출렁이지 않게 하기 위해서입니다.
- 순자산은 사람마다 한국시간 하루 한 줄씩 `asset_snapshots`에 기록됩니다. 5분마다 오늘 값을 갱신하고 1년간 보관합니다(`/api/asset-history`). 내 계좌 화면의 순자산 그래프가 이 기록을 씁니다.

### 10. 참여 기능

- **미션**: 매일 3개가 선정되고, 완료하면 건당 5만원의 모의 자금을 받습니다.
- **출석체크**: 매일 출석하면 연속 일수 단계(5단계)에 따라 하루 10만~50만원을 받습니다.
- **랭킹**: 전체 랭킹은 순자산 순입니다. 수익률에서는 출석·미션 보상, 관리자 지급액, 전광판 구매액을 뺍니다. 주간 랭킹은 한국시간 월요일 0시 자산을 기준으로 수익률을 계산하고, 월요일 0시에 주간 칭호를 지급합니다. 봇·데모·관리자 계정은 제외합니다.
- **칭호**: 거래·자산·랭킹 조건을 달성하면 얻고, 하나를 장착하면 랭킹에 표시됩니다. 주간 칭호는 여러 번 받을 수 있습니다(n관왕).
- **대출**: 순자산의 50%까지 빌릴 수 있고(최소 1만원), 하루 0.1% 이자가 붙습니다. 담보비율이 140% 아래로 내려가면 경고와 함께 신규 대출이 막힙니다. 120% 아래로 내려가면 미체결 주문을 취소하고 시장가로 팔아 빚을 갚습니다(반대매매).
- **전광판**: 홈 화면 상단에 2~40자 메시지를 1·3·6시간 동안 띄웁니다. 시간당 10만원(모의 자금)이고, 산 즉시 게시됩니다. 동시에 최대 10개가 10초마다 아래에서 올라오며 돌아가고, 마우스를 올리면 멈춥니다. 링크와 욕설은 막고, 사용자 신고와 관리자 숨김(환불 선택)이 있습니다.
- **프로필 사진**: 캐릭터 아바타 대신 직접 올린 사진을 쓸 수 있습니다. 2MB 이하 JPG·PNG·WebP를 받아 서버가 384px JPEG로 다시 그려 저장하고(사람당 1장), `/api/profile-photos/{id}.jpg`로 제공합니다.

### 12. 퀀트 전략과 자동 매매

블록을 끼워 맞추는 **BlockQuant**나 짧은 스크립트 언어 **snScript**로 전략을 만듭니다. 두 방식은 같은 프로그램으로 컴파일되고, 서버는 임의 코드를 실행하지 않고 허용된 문법 트리만 계산합니다.

```text
let fast = ta.sma(close, 5)
let slow = ta.ema(close, 20)
plot fastLine = fast
buy when ta.crossover(fast, slow) quantity 2
sell when ta.crossunder(fast, slow) quantity 2
```

- 쓸 수 있는 값은 `open`, `high`, `low`, `close`, `volume`(체결 건수)과 `sma`·`ema`·`rsi`·`stddev`·`atr`·`crossover`·`crossunder`·`abs` 함수입니다. 변수 32개, plot 8개, 규칙 8개까지입니다.
- **백테스트**: 완성된 캔들의 종가로 신호를 계산하고 다음 캔들 시가에 수수료·슬리피지를 붙여 체결합니다. 매수 후 매도만 하는 단순 모델이라 실제 자동 매매 결과와 다를 수 있습니다.
- **자동 매매**: 저장한 전략을 켜면 시장 서버가 2초마다 확인해서, 완성된 마지막 캔들에서 처음 참이 된 규칙 하나만 **지정가 주문**으로 냅니다. 로그아웃해도 계속 돌아갑니다. 주문 횟수(최대 100회)와 누적 주문 금액 한도를 넘으면 멈추고, 잔고·가격제한 같은 일반 주문 검증을 그대로 받습니다.
- 결과가 애매한 주문은 `UNKNOWN`으로 표시하고 전략을 멈춥니다. 자동으로 다시 주문하지 않으니 주문 내역을 확인한 뒤 다시 켜야 합니다. 본인 전략은 20개까지 저장할 수 있습니다.

### 13. 무료 DB 범위를 지키는 데이터 정리

운영 DB는 OCI MySQL Always Free(스토리지 50GB, 백업 50GB)입니다. 용량이 계속 늘지 않도록 백엔드가 2분마다 한 번에 일정량씩 오래된 데이터를 정리합니다.

| 데이터                       | 보관 방식                                                                                                                                             |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 가격 이력                    | 2일까지 원본. 2~8일은 분마다, 8일~1년은 시간마다 시가·종가·고가·저가 4점만 남김. 1년이 지나면 삭제. 차트 봉 단위가 이보다 크므로 차트 모양은 같습니다 |
| 봇끼리의 체결·정산·완료 주문 | 30일 후 삭제(유동성·지표 집계에 이미 반영된 것만)                                                                                                     |
| 봇 상세 체결 기록            | 초 단위 15분, 분 단위 8일, 시간 단위 370일                                                                                                            |
| 종목 토론 글                 | 원글 작성 후 7일(답글·좋아요 포함)                                                                                                                    |
| 일별 순자산                  | 1년                                                                                                                                                   |
| 거래 제한 기록               | 90일                                                                                                                                                  |
| 주문 처리 영수증             | 1시간                                                                                                                                                 |

**사람이 참여한 체결·주문·정산 기록은 지우지 않습니다.** 단, 관리자가 회원을 완전 삭제하면 그 회원의 기록은 상대방과의 체결·정산까지 함께 지워집니다.

### 14. ETF·선물·옵션

주식 계좌의 현금을 그대로 쓰는 모의 파생 상품입니다. 별도 파생 계좌는 없고, 평가액은 총자산과 랭킹에 포함됩니다. 계정을 초기화하면 열린 파생 포지션과 거래 원장도 함께 지웁니다.

| 상품         | 계약·가격                                                                | 수수료        | 정산                                              |
| ------------ | ------------------------------------------------------------------------ | ------------- | ------------------------------------------------- |
| 카테고리 ETF | RPG·액션·FPS·얼터너티브 바스켓, NAV 1좌                                  | 0.1%          | NAV 즉시 매매                                     |
| 지수 ETF     | `ETFIDX`, 전 종목 시가총액 가중                                          | 0.1%          | NAV 즉시 매매                                     |
| 지수 선물    | `FUTIDX` 무기한, 1계약=지수 1포인트×1,000원, 2x/5x/10x                   | 명목가 0.02%  | 증거금 예약, 평가액이 증거금 10% 이하이면 강제청산 |
| 옵션         | 유럽형 콜·풋 매수, 행사가 5포인트 단위(지수 ±2%), 1계약=1포인트×1,000원 | 프리미엄 0.3% | 만기 내재가치 현금결제, 만기 전 프리미엄 청산     |

옵션 만기는 세 회차입니다.

- **10분 만기**: 매 10분 정각(`:00`, `:10`, …)에 만기되는 0DTE 성격의 회차
- **1시간 만기**: 매시 정각에 만기되는 주간 회차
- **일요일 18:00 만기**: 한국시간 일요일 18:00에 만기되는 월간 회차. 일요일 18:00이 지나면 다음 주 일요일로 넘어갑니다.

프리미엄은 무위험 이자율 0의 블랙-숄즈와 최근 지수 실현 변동성으로 계산합니다. 만기에는 콜 `max(0, 지수−행사가)`, 풋 `max(0, 행사가−지수)`의 내재가치로 현금결제합니다. 지수 기준가는 최근 60초 체결로 검증하고, 거래가 드물면 최대 10분까지 실제 체결을 거슬러 찾습니다. 증거가 부족하면 거래를 보류합니다. API는 `GET /api/derivatives`(공개), `GET /api/derivatives/account`, `POST /api/derivatives/positions`, `POST /api/derivatives/positions/{id}/close`이고, 포지션은 `derivative_positions`, 원장은 `derivative_trades`에 저장합니다.

## 봇의 역할

봇은 **사람이 적어도 시장이 살아 있게 만드는 참여자**입니다. 가격을 직접 정하지 않고, 사람과 같은 호가창·같은 매칭 규칙으로 주문을 냅니다. 그래서 사람이 큰 매수 주문을 내면 봇이 내놓은 매도 호가를 실제로 소화하며 가격이 오릅니다.

### 참여자 봇 (기본 6,020명)

각자 하나의 종목을 맡고(20개 종목에 나눠 배정), 자기 전략과 성향(판단 주기, 반응 지연, 보유 기간, 위험 성향)에 따라 주문합니다.

| 전략 계열               | 예시 전략                                                | 성격                             |
| ----------------------- | -------------------------------------------------------- | -------------------------------- |
| 모멘텀                  | 빠른·느린 모멘텀, 돌파, 추세 추종, 눌림목, 거래량 모멘텀 | 오르는 쪽에 올라탐               |
| 역추세                  | RSI 역행, Z-점수, VWAP 회귀, 과열 소진, 급등 되돌림      | 과하게 움직이면 반대로           |
| 가치                    | 저평가 매수, 공격적·보수적 가치, 촉매 가치               | 내재가치보다 싸면 사고 비싸면 팜 |
| 단타                    | 스캘퍼, 호가 불균형, 미세 추세, 스프레드 테이커          | 짧은 시간의 작은 움직임          |
| 뉴스                    | 뉴스 반응, 뉴스 회의                                     | 뉴스에 반응하거나 일부러 반대로  |
| 스윙·노이즈·유동성 소비 | 스윙 추세, 무작위 흐름, 유동성 테이커                    | 다양한 주문 흐름 공급            |

- 신규 주문은 보통 5~10주이고, 최대 30초 동안 유효합니다. 살 돈이 부족하면 매수하지 않습니다.
- 봇은 자기 현금과 보유 주식 범위 안에서만 거래합니다. 돈을 새로 만들어 내지 않습니다.
- 한 종목 봇들의 돈이 바닥나 거래가 멈추지 않도록, 트레이더 봇은 하나의 **투자자 자금 풀**을 공유합니다. 30초마다 평균보다 많이 가진 봇의 여유 현금을 살 돈이 없는 봇에게 옮깁니다. 이때 전체 현금 합은 그대로이고, 주문에 묶인 예약 현금은 건드리지 않습니다.
- 봇의 일일 가격 범위는 ±20%로, 사람(±30%)보다 좁습니다. 소형주가 한계선에 가까워지면 추격 매매를 줄입니다.

### 유동성 공급 봇 (LP, 1개)

- 모든 종목에 매수·매도 호가를 최대 4단계, 단계당 최대 32주씩 냅니다. 사람이 언제 주문해도 상대 호가가 있도록 하는 시장 조성자입니다.
- 재고가 너무 많으면 팔고, 부족하면 다시 삽니다. 호가가 얇아지면 다음 정기 갱신을 기다리지 않고 바로 다시 채웁니다.
- 봇끼리 체결할 때 각 LP 호가의 마지막 1주는 사람 주문 몫으로 남겨 둡니다.
- LP가 번 순이익은 트레이더 자금 풀로 돌려보내서, 시장의 돈이 LP 한쪽에 쌓이지 않게 합니다.

### 선물·옵션 봇 (기본 48개)

- 선물 24개, 옵션 24개 계좌가 각각 100만원으로 시작합니다. 추세 추종, 역추세, 롱·콜 선호, 숏·풋 선호 성향을 나눠 가집니다.
- 사람과 같은 `DerivativeService`로 거래해서 증거금·프리미엄·수수료를 실제로 내고, 강제청산과 만기 정산도 똑같이 받습니다. 한 번에 한 포지션, 최대 2계약·명목 300만원까지이고, 손실을 봐도 자금을 보충받지 않습니다.
- 각자 9~30초마다 판단하고, 손절·익절·방향 전환·보유 시간·만기 임박 조건으로 청산합니다.
- 이 봇들과 사람의 파생 포지션이 쏠린 정도가 현물 봇의 주문 압력으로 이어집니다([가격이 정해지는 방식](#3-가격이-정해지는-방식) 참고).

### 봇 운영 원칙

- 봇끼리의 체결에는 수수료가 없습니다. 반복 거래로 시뮬레이션 자금이 사라지지 않게 하기 위해서입니다. 사람이 낀 체결에는 수수료가 정상적으로 붙습니다.
- 봇끼리의 체결은 개별 행 대신 초·분·시간 단위 집계로 저장해서 DB 쓰기를 줄입니다. 사람이 낀 체결은 일반 원장에 모두 남깁니다.
- 봇·데모·관리자 계정은 랭킹에서 빠지고, 토론 글쓰기와 퀀트 자동 매매를 쓸 수 없습니다.
- 관리자는 봇 전체 또는 트레이더만 멈추거나, 매칭 주기와 종목당 체결 목표를 바꿀 수 있습니다. 트레이더를 다시 켤 때는 일부부터 서서히 늘리도록 설정할 수 있습니다.

## 로컬 실행

백엔드(8081)와 웹(5180)은 **동시에 실행해야 합니다.** 웹은 화면만 담당하고 시세·주문·로그인·잔고는 모두 백엔드 API에서 가져오므로, 둘 중 하나만 켜면 화면이 비거나 요청이 실패합니다. 아래 2번과 3번을 터미널 두 개에 나란히 띄워 두세요.

### 준비물

- Node.js 20.19 이상 또는 22.12 이상, npm
- Java 17, Maven 3.9 이상
- MySQL 8
- Firebase 프로젝트(Google·이메일/비밀번호 로그인 사용 설정)와 Firebase Admin 서비스 계정 키

### 1. 데이터베이스

새 개발 DB에서 한 번만 실행합니다.

```sql
SOURCE C:/path/to/GameStock/database/schema.sql;
```

`schema.sql`은 초기 생성용입니다. 이후에 추가된 테이블·컬럼·인덱스·기본 종목은 백엔드가 시작할 때 스스로 보완합니다. 마이그레이션은 DB 잠금으로 보호되어 서버 두 대가 동시에 실행하지 않습니다.

### 2. 백엔드 (터미널 1)

```powershell
$env:DB_URL = 'jdbc:mysql://localhost:3306/gamestock?useUnicode=true&characterEncoding=utf8&serverTimezone=UTC&connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true'
$env:DB_USERNAME = '개발_DB_사용자'
$env:DB_PASSWORD = '개발_DB_비밀번호'
$env:FIREBASE_SERVICE_ACCOUNT_PATH = 'C:\path\to\firebase-admin.json'
$env:GAMESTOCK_CORS_ORIGIN = 'http://localhost:5180'

Set-Location backend
mvn spring-boot:run
```

API는 `http://localhost:8081`에서 열립니다. DB 세션은 UTC를 쓰고, 출석·미션·주간 집계 같은 서비스 날짜는 한국시간으로 계산합니다. `scripts/run-backend.ps1`은 루트 `.env`를 읽어 실행하지만, 특정 PC의 Java·Maven 경로에 맞춰져 있어서 다른 환경에서는 위 방법을 권장합니다.

### 3. 웹 (터미널 2)

백엔드를 띄운 **별도 터미널**에서 실행합니다. 저장소 루트에서 실행합니다.

```powershell
Copy-Item .env.example .env.local
npm ci
npm run dev
```

`.env.local`의 `VITE_API_BASE_URL`을 `http://localhost:8081`로, `VITE_FIREBASE_*`를 내 Firebase 프로젝트 값으로 바꿉니다. 웹은 http://localhost:5180 에서 열립니다.

두 서버가 함께 떠 있는지 확인합니다. http://localhost:5180 이 열리고 http://localhost:8081/api/health 가 `{"status":"ok",...}`를 반환해야 합니다. 웹만 켜져 있으면 화면은 뜨지만 시세·잔고·주문은 모두 실패합니다.

```powershell
npm run typecheck   # 타입 검사
npm run build       # dist/ 생성
npm run preview     # 빌드 결과 미리보기
```

`VITE_API_BASE_URL`이 비어 있으면 개발 모드는 `http://localhost:8081`을, 프로덕션 빌드는 운영 API를 씁니다. 주문을 시험하기 전에 어느 서버에 연결됐는지 꼭 확인하세요.

### 4. 모바일 앱

```powershell
Set-Location mobile
npm ci
# 로컬 백엔드를 쓸 때만 지정 (기본값은 운영 API)
$env:EXPO_PUBLIC_API_BASE_URL = 'http://PC의_LAN_IP:8081'
$env:EXPO_PUBLIC_WEB_APP_URL = 'http://PC의_LAN_IP:5180'
npm start
```

휴대폰에서 로컬 서버에 접속하려면 웹을 `npm run dev -- --host 0.0.0.0`으로 띄우고, 백엔드 CORS에 그 주소를 추가합니다.

앱 안 Google 로그인은 네이티브 모듈을 쓰므로 Expo Go가 아니라 개발 빌드(`npx expo run:android`, `npx expo run:ios` 또는 EAS 빌드)에서 동작합니다. Expo Go에서는 웹 로그인 방식으로 대신 진행합니다.

## 배포와 운영

| 대상      | 방식                                                                                                                                                                                                                           |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 웹        | `main`에 푸시하면 `.github/workflows/firebase-hosting.yml`이 타입 검사·빌드 후 Firebase Hosting에 배포                                                                                                                         |
| 백엔드    | `backend/**`가 바뀐 채 `main`에 푸시하면 `.github/workflows/oci-backend.yml`이 Java 17 테스트·빌드 → 체크섬 검증한 JAR 전송 → 기존 프로세스 종료 → 새 버전 기동 → API·스케줄러·호가·HTTPS·WSS 확인. 실패하면 이전 JAR로 되돌림 |
| 장애 감시 | `backend/ops/monitor.py`를 운영 서버가 아닌 별도 Linux 서버에서 systemd 서비스로 실행. 감시 스크립트가 바뀌면 `.github/workflows/monitor-checks.yml`이 테스트와 서비스 설정을 검증                                              |
| DB        | OCI MySQL HeatWave `MySQL.Free`(1 ECPU, 8GB 메모리, 50GB 스토리지), 사설망 TLS 연결, 하루 1회 자동 백업(1일 보관)                                                                                                              |
| 서버      | OCI VM(Oracle Linux 9 ARM64), `gamestock.service`(systemd), Nginx가 HTTPS와 `/ws/market`, `/ws/stream` 프록시                                                                                                                  |

- 매칭 엔진은 한 번에 하나만 실행합니다. DB 소유권 잠금으로 두 서버가 동시에 매칭하지 않게 막습니다.
- **DB가 끊겼다 돌아오면 매칭이 자동으로 재개됩니다.** 2026-11-04 Oracle MySQL 자동 업그레이드 후 매칭이 멈췄던 장애를 계기로, 별도 스레드가 2초마다 연결을 검증하고 실패하면 신규 매칭을 막은 뒤 새 연결로 소유권 잠금을 다시 얻습니다. 복구 중에는 `/api/health/ready`가 HTTP 503 `{"status":"recovering"}`, 준비되면 200 `{"status":"ready"}`를 반환합니다.
- **Discord 장애 알림**: 감시 서버가 30초마다 웹·API·DB 준비 상태·두 WebSocket 경로를 병렬로 확인합니다. 실패하면 3초 뒤 한 번 더 확인하고, 그래도 실패하면 알림을 보냅니다. 같은 장애가 이어지면 30분마다 다시 알리고, 복구되면 경과 시간과 함께 알립니다. 설치 절차는 [Discord 장애 알림](docs/discord-monitoring.md)에 있습니다.
- 서버의 논리 백업은 매일 한국시간 03:30에 만들고 7일 보관합니다.
- 무료 범위를 유지하려면 OCI 콘솔에서 DB 사양 변경, HeatWave 클러스터·고가용성·읽기 복제본 추가, 스토리지 자동 확장, 백업 보관 기간 연장을 하지 않아야 합니다. 비용이 생기면 바로 알 수 있도록 월 SG$1 예산을 만들어 두었습니다.
- 운영·백업·복구 절차는 [OCI 운영 문서](docs/oci-operations.md)에 있습니다. 예전 Railway 설정(`railway.json`)은 롤백 참고용으로만 남아 있습니다.

## 한계와 주의사항

- **모의 시장입니다.** 실제 돈·주식·게임 재화와 아무 관련이 없고, 투자 조언이 아닙니다.
- 종목 규모(이용자 수·시가총액)는 시뮬레이션용 입력값이며 실제 통계가 아닙니다.
- 뉴스 영향 점수는 키워드 규칙 기반이라 반어·문맥을 놓칠 수 있습니다. 공식 발표는 사이트 구조가 바뀌면 수집이 멈출 수 있습니다.
- 봇의 체결 목표는 목표일 뿐 체결량이나 유동성을 보장하지 않습니다. 거래 정지·자원 부족·DB 지연 중에는 호가가 비는 순간이 생길 수 있습니다.
- 접속자가 없는 동안에는 시장이 거의 멈춰 있습니다. 의도한 동작입니다.
- 퀀트 백테스트는 단순 모델이라 실제 자동 매매 결과와 다를 수 있고, 자동 매매는 분산 장애 상황에서 정확히 한 번 체결을 보장하지 않습니다.
- 차트의 거래량(`volume`)은 주 수가 아니라 체결 건수입니다.
- 종목 채팅은 폴링 방식이라 약 2초 늦게 보일 수 있습니다.
- 무료 DB(1 ECPU)를 쓰기 때문에 동시 접속이 아주 많으면 응답이 느려질 수 있습니다. DB가 중단된 동안에는 주문을 처리할 수 없습니다.
- 관리자의 회원 완전 삭제는 되돌릴 수 없고, 상대방 계좌의 체결·정산 기록도 함께 지워집니다.
- 실물 기기의 앱 안 Google 로그인 전체 흐름은 별도 확인이 필요합니다.
