# 슈엔증권 (GameStock)

> **이 서비스에 사용된 모든 저작물의 소유자는 각 게임사 및 제작사에 있으며 비영리의 목적으로 운영됨을 알려드립니다.**

**내가 좋아하는 게임에 투자해 그 게임의 값을 올리는 모의 주식 게임.**

서브컬처 게임 15종을 가상 주식 종목으로 상장했습니다. 사용자는 슈엔증권 프랍 데스크에 **수습 트레이더**로 입사해 회사 돈 100만원으로 게임 주식을 사고팔고, 실제 게임 뉴스와 다른 투자자들의 주문이 가격을 움직이는 과정을 실시간으로 지켜봅니다. 성과를 내면 사원·대리·과장을 거쳐 이사까지 승진하고, 운용한도와 성과급이 커집니다. 서비스 이름은 **슈엔증권**, 저장소와 백엔드 프로젝트 이름은 **GameStock**입니다.

- 웹: https://gamestock-20994.web.app / https://syuenasset.xyz
- API: https://gamestock-api.161-33-33-45.sslip.io (상태 확인 `/api/health`, 준비 확인 `/api/health/ready`)
- 모바일: Expo(React Native) 앱, Android·iOS 대상
- 외부 프로그램용 OpenAPI: 웹 상단 **API** 메뉴(`/api-docs`)

> 모의 투자 서비스입니다. 실제 주식·현금·게임 재화를 거래하지 않으며, 화면의 모든 금액은 가상 자금입니다.

## 만든 의도

서브컬처 게임 팬들은 자기가 하는 게임에 대한 애정이 큽니다. 커뮤니티에서는 "우리 게임이 더 잘나간다"는 이야기로 자주 경쟁이 붙습니다. 슈엔증권은 그 경쟁을 **주식 시장**으로 옮겨 왔습니다.

- **내 게임을 사서 값을 올린다.** 좋아하는 게임의 주식을 많은 사람이 사면 실제 매수 주문이 호가를 소화하면서 가격이 오릅니다. 팬덤의 응원이 숫자로 보입니다.
- **게임끼리 경쟁이 붙는다.** 시장 지도·히트맵과 "오늘 많이 움직인 종목"에서 어떤 게임이 오르고 내리는지 바로 비교할 수 있습니다. 주력 게임을 정하면 랭킹의 **팬덤전**에서 게임별 팬 수와 팬들의 주간 수익률로 겨룹니다. 대형 업데이트나 논란 같은 실제 뉴스와 공식 공지도 가격에 반영됩니다.
- **투자 실력도 겨룬다.** 트레이더·이번 주·시즌 랭킹과 칭호가 있어서 "어떤 게임을 언제 샀는가"로 다른 사용자와 겨룹니다.
- **다음 목표가 늘 보인다.** 수습에서 이사까지 7단계 직급이 있고, 승진할 때마다 운용한도가 커지고 선물·옵션·퀀트 같은 새 데스크가 열립니다.
- **시장이 어떻게 움직이는지 배운다.** 가격은 난수가 아니라 호가와 체결로 정해집니다. 뉴스 → 주문 → 호가 → 체결 → 가격으로 이어지는 흐름을 직접 관찰할 수 있도록 만들었습니다.
- **보상 체계.** 실제 금전은 걸 수 없으니, 칭호와 성과급·개인 지갑으로 모으는 재미를 줍니다. 개인 지갑의 돈은 전광판 광고나 탭 베팅처럼 매매 밖의 곳에 씁니다.

사람이 적은 시간에도 시장이 비어 보이지 않도록, 서버에서 6,020명 규모의 전략 봇과 유동성 공급 봇이 사람과 같은 호가창에서 거래합니다. 봇은 가격을 정해 주는 장치가 아니라, 사람과 같은 규칙으로 주문을 내는 시장 참여자입니다. 자세한 내용은 [봇의 역할](#봇의-역할)에 있습니다.

## 핵심 흐름 한눈에 보기

```text
 실제 게임 뉴스(RSS)·공식 공지          사람의 주문 (웹·앱·OpenAPI)
        │                                   │
        ▼                                   ▼
 관련성 필터 → 영향 점수(-10~+10)     주문 접수·검증 (잔고·가격제한·VI·직급 한도)
        │                                   │
        ▼                                   ▼
 종목 내재가치·합의가치 갱신 ──▶ 봇 판단 ──▶ 같은 호가창에서 가격·시간 우선 매칭
                                            │
                                            ▼
                               체결 → DB 커밋 → 현재가 변경
                                            │
                                            ▼
                     WebSocket으로 시세·호가·체결·내 계좌 전송 (웹·앱)
```

**현재가는 실제 체결로만 바뀝니다.** 뉴스나 봇이 가격을 직접 써넣지 않습니다. 뉴스는 봇이 생각하는 적정 가치를 바꾸고, 그 생각이 주문이 되고, 주문이 체결될 때 비로소 가격이 움직입니다.

```text
┌──────────── 웹 (React) ─────────────┐   ┌──────── 모바일 (Expo) ────────┐   ┌─ 외부 프로그램 ─┐

       └───────────────┴──────────────┬─────────────┴───────────────┴──────────────────┘
                                      ▼
                 Nginx (HTTPS·WSS) ─▶ Spring Boot (OCI VM, 127.0.0.1:8081)
                 ├─ 주문 접수 → 메모리 호가 매칭 → 배치 DB 저장 (영수증으로 중복 방지)
                 ├─ 봇 스케줄러: 4개 종목 그룹, 접속자 있을 때만 상시 매칭
                 ├─ 거래 보호: 가격제한폭 · VI · 서킷브레이커 · 단일가 · 주문 속도 제한
                 ├─ 손절·익절 감시(1초), 퀀트 전략 자동매매(2초)
                 ├─ 뉴스 수집(10분) · 공식 공지 수집(1시간) · 본문 발췌 · 영향 분석
                 ├─ 커리어 정산(성과급·승진·강등), 대출 이자·담보 감시, 랭킹·칭호·시즌, 미션
                 ├─ 공개 시세 캐시 (변경 시에만 DB 재조회)
                 ├─ 장부 불변식 점검(10분), DB 풀 지표
                 └─ 오래된 데이터 정리 (무료 DB 용량 유지)
                                      │ TLS, 사설망
                                      ▼
                          MySQL (OCI, gamestock 스키마)

 별도 Linux 서버: 감시기(30초) ─▶ 웹·API·WebSocket 확인 ─▶ Discord 장애·복구 알림
```

- 웹과 앱은 같은 백엔드, 같은 실시간 스트림, 같은 Firebase 인증을 사용합니다.
- 로그인하지 않아도 시장·종목·뉴스·랭킹·종목토론을 볼 수 있습니다. 주문과 계좌·커리어 화면에는 로그인이 필요합니다. 로그인하면 원래 보던 화면으로 돌아갑니다.
- 실시간 연결이 끊기면 웹은 지수 백오프(최대 15초)로 재연결하고, 연결 상태를 확인하는 하트비트와 4분마다 인증 갱신을 보냅니다.
- 뉴스 RSS·공식 공지·기사 발췌처럼 외부 사이트를 읽는 작업은 전용 스레드 2개에서 따로 돌립니다. 외부 사이트가 느려도 시세 방송이나 손절 감시가 밀리지 않습니다.

## 기능이 돌아가는 원리

### 1. 주문과 매칭

1. 주문이 들어오면 서버가 종목·수량(1~1,000주)·주문 유형을 검증하고, 거래 보호 상태(VI·서킷브레이커·거래 정지)와 직급 한도(일일 손실한도·종목 집중 한도)를 확인합니다.
2. 사람 주문은 전용 접수 큐에 쌓이고, 2ms 동안 모인 주문을 최대 200건까지 한 트랜잭션으로 처리합니다. 봇 주문보다 먼저 처리됩니다.
3. 매칭은 **가격 우선, 같은 가격이면 시간 우선**입니다. 매수 지정가는 그 가격 이하의 매도 호가와, 시장가는 실행 범위(기준가 ±10%) 안의 가장 좋은 호가와 체결됩니다. 체결되지 않은 지정가 수량은 호가창에 남습니다.
4. 매수 주문은 필요한 현금을 **예약**하고, 매도 주문은 보유 수량을 예약합니다. 미체결 주문을 취소하면 예약이 풀립니다. 그래서 같은 돈이나 주식을 두 번 쓸 수 없습니다.
5. 체결 결과는 **DB에 커밋된 뒤에만** 성공으로 응답합니다. 주문 배치마다 영수증을 함께 저장하고, 웹·앱은 주문마다 중복 방지 키를 보내서, 응답이 유실돼 다시 시도하더라도 주문이 두 번 실행되지 않습니다.
6. 주문 남발을 막기 위해 계정별로 주문은 순간 20건·이후 초당 2건, 취소는 순간 60건·이후 초당 10건까지 받습니다. 넘으면 429와 함께 잠시 뒤 다시 하라는 안내가 나옵니다.

### 2. 손절·익절 자동 매도

- 보유 종목에 **손절(STOP_LOSS)** 은 현재가보다 낮은 가격에, **익절(TAKE_PROFIT)** 은 높은 가격에 겁니다. 수량은 1~1,000주(보유 수량 이하)이고 계정당 동시에 10개까지입니다.
- 서버가 1초마다 확인해 감시 가격에 닿으면 시장가로 매도합니다. 보유 수량이 0이 되면 같은 종목의 다른 감시 주문도 끝납니다.

### 3. 가격이 정해지는 방식

- 현재가는 **마지막 체결가**입니다. 체결이 없으면 가격도 그대로입니다.
- 각 종목에는 실제 게임 이용자 규모를 본뜬 가상 규모(시가총액·유동성)가 있습니다. 대형주 8개는 천천히, 소형주 7개는 크게 움직입니다. 이 수치는 시뮬레이션 입력값이며 실측 통계가 아닙니다.
- 봇은 **합의 가치**(시장 참여자들이 생각하는 적정가) 주변에서 호가를 냅니다. 합의 가치는 종목 규모에 맞춘 무작위 걸음으로 조금씩 움직이고, 시장 국면을 따라 흐르며, 뉴스가 바꾼 목표가 쪽으로 수십 분에 걸쳐 끌려갑니다. 뉴스가 나오자마자 가격이 순간이동하지 않는 이유입니다.
- 게임주 지수는 15개 종목을 시가총액 비중으로 담은 지수 ETF(`ETFIDX`)의 NAV입니다. 처음 1000에서 시작했고, 자정에 다시 1000으로 돌아가지 않고 전날 종가에서 이어집니다. 등락률은 전날 종가 대비이고, 선물·옵션도 이 지수를 따릅니다.

### 4. 뉴스와 공식 발표 분석

1. **뉴스 수집**: 10분마다 종목별 Google 뉴스 RSS를 가져옵니다(게임 이름으로 검색 주소를 자동 생성).
2. **공식 발표 수집**: 1시간마다 니케(한국 공식 사이트 공지), 우마무스메(공식 카페 공지·업데이트), 블루 아카이브(넥슨 포럼 공지·업데이트) 게시판을 읽습니다. 공식 발표는 같은 크기의 언론 기사보다 1.5배 크게 반영합니다. 처음 수집할 때 이미 있던 글은 목록에만 넣고 가격에는 반영하지 않습니다.
3. **관련성 필터**: 제목·본문이 그 게임에 관한 기사인지 규칙으로 판별하고, 같은 기사의 중복 게재를 하나로 묶습니다.
4. **영향 점수**: 가중 키워드 규칙으로 -10~+10 점수를 매깁니다. 대규모 업데이트·흥행·매출 증가는 양수, 서비스 장애·논란·소송은 음수입니다. 생성형 AI나 학습된 예측 모델은 쓰지 않습니다.
5. **본문 발췌**: 원문 주소를 풀어 기사 첫 문단을 미리 저장해 둡니다. 화면에서는 저장된 발췌를 바로 보여 줍니다.
6. **가격에 미치는 경로**: 최근 24시간 안의 관련 뉴스 10건이 시간이 지날수록 약해지는 가중치로 합산됩니다. 이 값이 종목의 내재가치와 합의 가치 목표를 움직이고, 뉴스 반응형 봇은 각자의 반응 지연 시간이 지난 뒤 주문을 냅니다.

뉴스 화면의 "발행 이후 가격 변화"는 다른 거래와 시장 요인도 포함한 값입니다. 그 기사 하나의 효과만 뜻하지 않습니다.

### 6. 실시간 전송

- 서버는 종목별로 직렬화한 스냅샷 하나를 만들어, 그 종목을 구독한 모든 연결에 같은 메시지를 보냅니다. 연결 수가 늘어도 종목당 계산은 한 번입니다.
- 내 계좌(잔고·보유·주문 상태)는 로그인한 연결에만 개인 채널로 보냅니다. 보유 종목 평가액은 2초마다 다시 계산하고, 바뀐 경우에만 보냅니다.
- 첫 화면이 기다리는 공개 시세·시장 상태·뉴스는 서버가 미리 계산해 둡니다. 체결이나 정비가 커밋됐을 때만 DB를 다시 읽고, 뉴스는 수집·발췌가 저장됐을 때만 다시 읽습니다.

### 7. 접속에 따라 바뀌는 시장 속도

- 웹·앱 접속(WebSocket 연결 또는 API 요청)이 있으면 **활성 모드**입니다. 4개 종목 그룹이 250ms 간격으로 봇 매칭을 돌리고, 종목당 초당 체결 목표에 맞춰 주문량을 정합니다.
- 마지막 접속 후 2분이 지나면 **유휴 모드**로 내려갑니다. 30분마다 짧은 매칭(배치 5회)만 하고, 쉬는 동안 밀린 체결을 나중에 몰아서 만들지 않습니다.
- 상태 확인(`/api/health`, `/api/health/ready`), 지표(`/api/market-metrics`), 프로필 사진 요청과 봇 자신의 활동은 접속으로 치지 않습니다.

### 8. 정산과 계좌

- 체결 즉시 정산됩니다. 매수자는 주식을, 매도자는 대금을 바로 받습니다.
- 사람이 참여한 체결에는 매수·매도 각각 0.1% 수수료가 붙습니다.
- 총자산 = 현금 + 주문에 묶인 예약 현금 + 보유 종목 평가액 + ETF·파생 평가액 − 대출 잔액. 평가액은 최근 체결 흐름과 호가로 계산한 평가 가격(mark price)을 씁니다. 한 번의 튀는 체결로 자산이 출렁이지 않게 하기 위해서입니다.
- 순자산은 5분마다 그날 값으로 기록해 1년간 보관하고, 내 계좌 화면의 자산 추이 차트로 보여 줍니다.

### 9. 참여 기능

참여 보상은 모두 매매용 운용계좌가 아니라 **개인 지갑**으로 들어갑니다([커리어와 두 계좌](#커리어와-두-계좌) 참고).

- **출석**: 로그인하면 연속 출석 일수 × 1만원을 받고, 5일째부터는 매일 5만원입니다. 하루는 한국시간 자정에 바뀝니다.
- **미션**: 매일 3개가 선정되고, 완료하면 건당 1만원을 받습니다.
- **일일 예측**: 하루 한 종목을 22시 전에 고르고, 그날 종가가 고른 시점 가격보다 높으면 1만원을 받습니다.
- **랭킹**: 트레이더 랭킹은 운용계좌 순자산 순, 부자 랭킹은 개인 지갑 순입니다. 수익률에서는 관리자·회사가 넣어 준 돈을 뺍니다. 주간 랭킹은 한국시간 월요일 0시 자산을 기준으로 수익률을 계산하고, 월요일 0시에 주간 칭호를 지급합니다. 시장 봇·데모·관리자 계정은 제외합니다.
- **시즌**: 관리자가 시즌을 열고 닫습니다. 시작 자산 대비 증가액으로 순위를 매기고, 종료 때 순위별 보상(개인 지갑)과 1~3위 시즌 칭호를 줍니다.
- **팬덤전**: 회원이 고른 주력 게임(7일에 한 번 변경)별로 팬 수, 주주 수, 팬들의 주간 수익률을 겨룹니다.
- **칭호**: 거래·자산·랭킹 조건을 달성하면 얻고, 하나를 장착하면 랭킹에 표시됩니다. 주간 칭호는 여러 번 받을 수 있습니다(n관왕).
- **프로모션 코드**: 코드마다 현금(개인 지갑)이나 칭호 보상, 사용 인원, 기간이 있고, 한 계정은 한 코드를 한 번만 씁니다.
- **전광판**: 시간당 10만원으로 1·3·6시간 동안 문구(2~40자, 링크·욕설 차단)를 띄웁니다. 동시에 최대 10개가 홈 상단에서 10초씩 번갈아 나오고, 다른 회원이 신고할 수 있습니다.
- **대출**: 신규 대출은 중단했습니다. 운용계좌는 회사 돈이라 직급의 운용한도로만 굴립니다. 이미 빌린 대출에는 하루 0.1% 이자가 계속 붙고 갚을 수 있으며, 담보비율이 120% 아래로 내려가면 미체결 주문을 취소하고 시장가로 팔아 빚을 갚습니다(반대매매).

### 10. 탭 베팅

- 대형주 8종목(GI·SR·OW·ZZZ·WH·GOV·BA·UMA)의 실제 체결가로 판정합니다. 가로 한 칸은 5초 구간(앞으로 최대 8칸), 세로 한 칸은 1틱입니다.
- 칸이 열리기 1.5초 전까지 걸 수 있고, 현재가가 들어 있는 칸에는 걸 수 없습니다. 판돈은 5천·1만·5만원이고, 결과를 기다리는 베팅은 최대 24개, 1분에 120번까지입니다.
- 구간 안에 가격이 칸에 닿으면 당첨, 끝까지 닿지 않으면 낙첨입니다. 30초가 지나도 판정할 시세가 없으면 환불합니다. 베팅 기간에 그 종목을 직접 사고팔았다면 당첨이어도 판돈만 돌려줍니다.
- 배당은 닿을 확률에서 하우스 몫 8%를 뺀 값을 0.1 단위로 내린 것이고, 1.1×~30× 범위의 칸만 걸 수 있습니다. 확률은 실제 적중 기록으로 보정하고, 기록이 적을 때는 브라운 운동 확률을 섞어 씁니다.

### 11. 퀀트 전략

- 글로 쓰는 **snScript**와 블록으로 짜는 **BlockQuant** 두 방식이 있습니다. open·high·low·close·volume 값과 sma·ema·rsi·stddev·atr·crossover·crossunder·abs 함수를 씁니다.
- 한도: 변수 32개, 차트 표시선 8개, 규칙 8개(매수/매도, 1~1,000주), 지표 기간 2~500. 전략은 계정당 20개까지입니다.
- **백테스트**: 공매도 없는 모의 매매로, 봉 마감 신호를 다음 봉 시가에 체결합니다. 초기자금과 수수료·슬리피지를 정하고, 수익률·최대 낙폭·거절 주문 수·자산 곡선을 봅니다.
- **자동매매**: 2초마다 실행 중인 전략을 확인해, 새 봉이 마감되면 처음 맞는 규칙 하나로 현재가 지정가 주문을 냅니다. 전략마다 최대 주문 수와 최대 주문 총액을 정하고, 다 쓰거나 오류가 나면 스스로 멈춥니다. 자동 매수에도 직급·손실한도·종목 집중 한도가 그대로 적용되고, 강등되면 매도만 계속됩니다.

### 12. OpenAPI

- 외부 프로그램에서 `/api/openapi/v1`로 주식·ETF·선물·옵션 시세를 조회하고 자기 계좌로 거래합니다. 명세는 `GET /api/openapi/openapi.json`(OpenAPI 3.0.3)입니다.
- 시세는 인증 없이, 계좌·주문 조회는 `READ` 또는 `TRADE` 키, 주문·취소·청산은 `TRADE` 키가 필요합니다. 키는 로그인한 사용자가 `/api-docs`에서 발급하며, 원문은 발급 때 한 번만 보여 주고 서버에는 SHA-256 해시만 저장합니다. 계정당 활성 키 10개, 만기 1~365일(기본 90일)입니다.
- 추가 패키지 없는 Python 예제가 `examples/gamestock_openapi.py`에 있습니다. 자세한 내용은 [OpenAPI 문서](docs/openapi.md)에 있습니다.

### 13. 계정 관리

- **프로필 사진**: 기본 이미지 중 고르거나 JPEG/PNG(2MB, 한 변 4096px 이하)를 올립니다. 올린 사진은 384px 정사각 JPEG로 다시 그려 저장하므로 촬영 정보 같은 메타데이터가 남지 않습니다.
- **회원 탈퇴**(`DELETE /api/account`): 지금 닉네임을 입력해야 진행됩니다. 계정 정지 → 미체결·자동 주문 취소 → 회원과 연결된 기록 삭제 → Firebase 로그인 계정 삭제 순서로 처리합니다. 웹 설정과 앱 프로필 화면에서 할 수 있고, 관리자 계정은 탈퇴할 수 없습니다.

### 15. ETF·선물·옵션

주식 운용계좌의 현금을 그대로 쓰는 모의 파생 상품입니다. 별도 파생 계좌는 없고, 평가액은 총자산과 랭킹에 포함됩니다. 계정을 초기화하면 열린 파생 포지션과 거래 원장도 함께 지웁니다. 파생 주문 수량은 1~100입니다.

| 상품         | 계약·가격                                                                | 수수료        | 정산                                             |
| ------------ | ------------------------------------------------------------------------ | ------------- | ------------------------------------------------ |
| 카테고리 ETF | RPG·액션·FPS·얼터너티브 바스켓, NAV 1좌                                  | 0.1%          | NAV 즉시 매매                                    |
| 지수 ETF     | `ETFIDX`, 전 종목 시가총액 가중                                          | 0.1%          | NAV 즉시 매매                                    |
| 지수 선물    | `FUTIDX` 무기한, 1계약=지수 1포인트×1,000원, 2x/5x/10x                   | 명목가 0.02%  | 증거금 예약, 평가액이 증거금 10% 이하이면 강제청산 |
| 옵션         | 유럽형 콜·풋 매수, 행사가 5포인트 단위(지수 ±2%), 1계약=1포인트×1,000원 | 프리미엄 0.3% | 만기 내재가치 현금결제, 만기 전 프리미엄 청산    |

옵션 만기는 세 회차입니다.

- **10분 만기**: 매 10분 정각(`:00`, `:10`, …)에 만기되는 0DTE 성격의 회차
- **1시간 만기**: 매시 정각에 만기되는 주간 회차
- **일요일 18:00 만기**: 한국시간 일요일 18:00에 만기되는 월간 회차. 일요일 18:00이 지나면 다음 주 일요일로 넘어갑니다.

프리미엄은 무위험 이자율 0의 블랙-숄즈와 최근 지수 실현 변동성으로 계산합니다. 만기에는 콜 `max(0, 지수−행사가)`, 풋 `max(0, 행사가−지수)`의 내재가치로 현금결제합니다. API는 `GET /api/derivatives`(공개), `GET /api/derivatives/account`, `POST /api/derivatives/positions`, `POST /api/derivatives/positions/{id}/close`이고, 포지션은 `derivative_positions`, 원장은 `derivative_trades`에 저장합니다.


### 로그인 없이 체험하기

- 로그인 창과 주문 칸의 **로그인 없이 바로 체험하기**는 Firebase 익명 로그인으로 체험 계정(`password_hash='GUEST'`, 닉네임 `체험0000`)을 만듭니다. 신규 회원처럼 모의 자금 100만원과 수습 OJT로 시작합니다.
- 체험 계정은 트레이더·부자·주간·시즌 랭킹, 팬덤 집계, 체결 소식에서 빠집니다. 종목토론·채팅·전광판·공개 프로필·닉네임 변경·프로필 사진·프로모션 코드·OpenAPI 키는 가입한 뒤에 씁니다(서버 `AuthService.requireMember`).
- 같은 브라우저에서 가입하면 익명 계정에 Google·이메일 로그인을 붙여(`linkWithPopup`, `linkWithCredential`) UID가 그대로 남습니다. 서버는 다음 요청에서 일반 계정으로 바꾸고 자산·주문·커리어를 그대로 이어 줍니다. 이미 가입한 계정으로 로그인하면 체험 기록은 이어지지 않습니다.
- 앱(WebView) 안에서는 앱 로그인 흐름이 따로 있어 체험 버튼을 보이지 않습니다.
- 운영에 켜려면 Firebase 콘솔 → Authentication → 로그인 방법에서 **익명**을 사용 설정해야 합니다. 꺼져 있으면 체험 버튼이 "지금은 로그인 없이 체험하기를 쓸 수 없어요"를 보여 줍니다.

## 커리어와 두 계좌

### 운용계좌와 개인 지갑

| 계좌         | 성격     | 들어오는 돈                                                    | 쓰는 곳                        |
| ------------ | -------- | -------------------------------------------------------------- | ------------------------------ |
| 운용계좌     | 회사 돈  | 직급 운용한도 충전                                             | 주식·ETF·선물·옵션 매매        |
| 개인 지갑    | 내 돈    | 성과급, 출석·미션·예측·시즌·프로모션 보상, 기존 회원 퇴직금 | 탭 베팅, 전광판                |

- 돈은 한 방향으로만 흐릅니다. 개인 지갑의 돈은 운용계좌로 옮길 수 없어서, 보상으로 승진을 살 수 없습니다.
- 개인 지갑의 모든 변동은 원장(`personal_ledger`)에 남고, 같은 지급이 두 번 들어가지 않습니다.
- 회사가 넣어 주는 운용한도 충전은 외부 입금으로 기록해 수익률에 잡히지 않습니다.

### 직급

| 직급 | 운용한도 | 성과급률 | 다음 직급 승진 조건                                    | 강등선 | 열리는 기능  |
| ---- | -------- | -------- | ------------------------------------------------------ | ------ | ------------ |
| 수습 | 100만    | 0%       | OJT 5단계 완료                                         | 없음   | 현물 매매    |
| 사원 | 300만    | 10%      | +10% 정산 2회 연속, 거래일 3일, 체결 20회              | -20%   | 탭 베팅      |
| 대리 | 1,000만  | 15%      | +10% 정산 2회 연속, 거래일 5일, 뉴스 2시간 안 체결 5회 | -20%   | 선물         |
| 과장 | 3,000만  | 20%      | +12% 정산 3회 연속, 거래일 7일, 선물 청산 3회          | -20%   | 옵션         |
| 차장 | 1억      | 25%      | +12% 정산 3회 연속, 거래일 10일, 서로 다른 5종목 매도  | -15%   | 퀀트 전략    |
| 부장 | 3억      | 30%      | +15% 정산 3회 연속, 거래일 14일, 일일 손실한도 위반 0회 | -15%   | -            |
| 이사 | 10억     | 40%      | 최고 직급                                              | -15%   | -            |

- **OJT(수습)**: 주력 게임 고르기, 종목 화면 보기, 지정가 매수 체결, 매도 체결, 리스크 교육 확인.
- **기준자산**: 그 직급을 시작할 때의 운용계좌 자산입니다. 승진 목표, 강등선, 일일 손실한도, 종목 집중 한도는 모두 이 값에 대한 비율입니다.
- **승진 수익률**은 확정 기준(보유 주식은 산 값과 지금 값 중 낮은 쪽)으로 매일 0시 정산 때 셉니다. 한 번 아래로 마감하면 연속 횟수가 처음부터 다시 셉니다.
- **거래일·체결 조건**은 체결 금액이 기준자산의 1% 이상인 거래만 셉니다. 1주짜리 거래로 조건을 채울 수 없습니다.
- **승진·강등** 때는 운용한도보다 모자란 금액만큼 운용계좌를 충전합니다. 사원이 강등선을 넘으면 재교육으로 300만원을 다시 충전하고 24시간 동안 신규 매수를 막습니다.
- **성과급**: 하루 한 번, 확정자산이 이전 최고점을 넘은 만큼에 직급 성과급률을 곱해 개인 지갑에 넣습니다.
- 커리어 도입 전 가입한 기존 회원은 모든 기능이 열려 있고, 순자산의 10%(최대 1,000만원)를 퇴직금으로 개인 지갑에 받았습니다.

설계 배경과 남은 계획은 [프랍 트레이더 커리어 설계](docs/prop-career-design.md)에 있습니다. 문서는 초안이라 수치가 코드와 다른 곳은 코드(`CareerGrade.java`, `CareerService.java`)가 기준입니다.

## 봇의 역할

봇은 **사람이 적어도 시장이 살아 있게 만드는 참여자**입니다. 가격을 직접 정하지 않고, 사람과 같은 호가창·같은 매칭 규칙으로 주문을 냅니다. 그래서 사람이 큰 매수 주문을 내면 봇이 내놓은 매도 호가를 실제로 소화하며 가격이 오릅니다.

### 참여자 봇 (기본 6,020명)

각자 하나의 종목을 맡고, 자기 전략과 성향(판단 주기, 반응 지연, 보유 기간, 위험 성향)에 따라 주문합니다.

| 전략 계열               | 예시 전략                                                | 성격                             |
| ----------------------- | -------------------------------------------------------- | -------------------------------- |
| 모멘텀                  | 빠른·느린 모멘텀, 돌파, 추세 추종, 눌림목, 거래량 모멘텀 | 오르는 쪽에 올라탐               |
| 역추세                  | RSI 역행, Z-점수, VWAP 회귀, 과열 소진, 급등 되돌림      | 과하게 움직이면 반대로           |
| 가치                    | 저평가 매수, 공격적·보수적 가치, 촉매 가치               | 내재가치보다 싸면 사고 비싸면 팜 |
| 단타                    | 스캘퍼, 호가 불균형, 미세 추세, 스프레드 테이커          | 짧은 시간의 작은 움직임          |
| 뉴스                    | 뉴스 반응, 뉴스 회의                                     | 뉴스에 반응하거나 일부러 반대로  |
| 스윙·노이즈·유동성 소비 | 스윙 추세, 무작위 흐름, 유동성 테이커                    | 다양한 주문 흐름 공급            |

- 신규 주문은 5~15주이고, 최대 30초 동안 유효합니다. 살 돈이 부족하면 매수하지 않습니다.
- 봇은 자기 현금과 보유 주식 범위 안에서만 거래합니다. 돈을 새로 만들어 내지 않습니다.
- 한 종목 봇들의 돈이 바닥나 거래가 멈추지 않도록, 트레이더 봇은 하나의 **투자자 자금 풀**을 공유합니다. 30초마다 평균보다 많이 가진 봇의 여유 현금을 살 돈이 없는 봇에게 옮깁니다. 이때 전체 현금 합은 그대로이고, 주문에 묶인 예약 현금은 건드리지 않습니다.
- 봇의 일일 가격 범위는 ±20%로, 사람(±30%)보다 좁습니다. 소형주가 한계선에 가까워지면 추격 매매를 줄입니다.

### AI 트레이더 (운영 봇 5명)

- `Persona.java`의 운영 봇은 일반 회원과 같은 주문 경로로 거래하고 출석·예측·칭호도 챙깁니다. 화면은 이들의 닉네임 옆에 **AI** 표시를 붙입니다(랭킹·체결 소식·종목토론·채팅, `/api/engagement/ai-nicknames`).
- 하루 등락이 3% 넘는 종목이 있으면 가끔 종목토론에 자기 성격(장기·단타·초보)대로 짧은 감상을 남깁니다(`PersonaTalk.java`). 봇 한 명당 하루 3개, 같은 종목에는 3시간에 한 번까지이고, 사라고 권하는 말은 쓰지 않습니다.
- 보상 순위에 들어도 시즌 보상·주간 칭호는 받지 않습니다.

### 유동성 공급 봇 (LP, 1개)

- 모든 종목에 매수·매도 호가를 최대 4단계, 단계당 최대 32주씩 냅니다. 사람이 언제 주문해도 상대 호가가 있도록 하는 시장 조성자입니다.
- 재고가 너무 많으면 팔고, 부족하면 다시 삽니다. 호가가 얇아지면 다음 정기 갱신을 기다리지 않고 바로 다시 채웁니다.
- 봇끼리 체결할 때 각 LP 호가의 마지막 1주는 사람 주문 몫으로 남겨 둡니다.
- LP가 번 순이익은 트레이더 자금 풀로 돌려보내서, 시장의 돈이 LP 한쪽에 쌓이지 않게 합니다.

### 봇 운영 원칙

- 봇끼리의 체결에는 수수료가 없습니다. 반복 거래로 시뮬레이션 자금이 사라지지 않게 하기 위해서입니다. 사람이 낀 체결에는 수수료가 정상적으로 붙습니다.
- 봇끼리의 체결은 개별 행 대신 초·분·시간 단위 집계로 저장해서 DB 쓰기를 줄입니다. 사람이 낀 체결은 일반 원장에 모두 남깁니다.
- 시장 봇·데모·관리자·체험 계정은 랭킹에서 빠집니다.
- 관리자는 봇 전체 또는 트레이더만 멈추거나, 매칭 주기와 종목당 체결 목표를 바꿀 수 있습니다. 트레이더를 다시 켤 때는 일부부터 서서히 늘리도록 설정할 수 있습니다.

## 로컬 실행

백엔드(8081)와 웹(5180)은 **동시에 실행해야 합니다.** 웹은 화면만 담당하고 시세·주문·로그인·잔고는 모두 백엔드 API에서 가져오므로, 둘 중 하나만 켜면 화면이 비거나 요청이 실패합니다. 아래 2번과 3번을 터미널 두 개에 나란히 띄워 두세요.

### 준비물

- Node.js 24.22.1 이상, npm
- Java 17, Maven 3.9 이상
- MySQL 8
- Firebase 프로젝트(Google·이메일/비밀번호 로그인 사용 설정)와 Firebase Admin 서비스 계정 키

### 1. 데이터베이스

새 개발 DB에서 한 번만 실행합니다.

```sql
SOURCE C:/path/to/GameStock/database/schema.sql;
```

`schema.sql`은 초기 생성용입니다. 이후에 추가된 테이블·컬럼·인덱스·기본 종목은 백엔드가 시작할 때 스스로 보완합니다. 마이그레이션은 DB 잠금으로 보호되어 서버 두 대가 동시에 실행하지 않습니다.

### 2. 백엔드 (터미널 1)

```powershell
$env:DB_URL = 'jdbc:mysql://localhost:3306/gamestock?useUnicode=true&characterEncoding=utf8&serverTimezone=UTC&connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true'
$env:DB_USERNAME = '개발_DB_사용자'
$env:DB_PASSWORD = '개발_DB_비밀번호'
$env:FIREBASE_SERVICE_ACCOUNT_PATH = 'C:\path\to\firebase-admin.json'
$env:GAMESTOCK_CORS_ORIGIN = 'http://localhost:5180'

Set-Location backend
mvn spring-boot:run
```

API는 `http://localhost:8081`에서 열립니다. DB 세션은 UTC를 쓰고, 출석·미션·주간 집계·커리어 정산 같은 서비스 날짜는 한국시간으로 계산합니다. `scripts/run-backend.ps1`은 루트 `.env`를 읽어 실행하지만, 특정 PC의 Java·Maven 경로에 맞춰져 있어서 다른 환경에서는 위 방법을 권장합니다.

### 3. 웹 (터미널 2)

백엔드를 띄운 **별도 터미널**에서 실행합니다. 저장소 루트에서 실행합니다.

```powershell
Copy-Item .env.example .env.local
npm ci
npm run dev
```

`.env.local`의 `VITE_API_BASE_URL`을 `http://localhost:8081`로, `VITE_FIREBASE_*`를 내 Firebase 프로젝트 값으로 바꿉니다. 웹은 http://localhost:5180 에서 열립니다.

두 서버가 함께 떠 있는지 확인합니다. http://localhost:5180 이 열리고 http://localhost:8081/api/health 가 `{"status":"ok",...}`를 반환해야 합니다. 웹만 켜져 있으면 화면은 뜨지만 시세·잔고·주문은 모두 실패합니다.

```powershell
npm run typecheck   # 타입 검사 (e2e 포함)
npm run lint        # ESLint
npm test            # 웹 단위 테스트
npm run build       # dist/ 생성
npm run preview     # 빌드 결과 미리보기
```

`VITE_API_BASE_URL`이 비어 있으면 개발 모드는 `http://localhost:8081`을, 프로덕션 빌드는 `endpoints.json`의 운영 API를 씁니다. 주문을 시험하기 전에 어느 서버에 연결됐는지 꼭 확인하세요.

### 4. 모바일 앱

```powershell
Set-Location mobile
npm ci
# 로컬 백엔드를 쓸 때만 지정 (기본값은 운영 API)
$env:EXPO_PUBLIC_API_BASE_URL = 'http://PC의_LAN_IP:8081'
$env:EXPO_PUBLIC_WEB_APP_URL = 'http://PC의_LAN_IP:5180'
npm start
```

휴대폰에서 로컬 서버에 접속하려면 웹을 `npm run dev -- --host 0.0.0.0`으로 띄우고, 백엔드 CORS에 그 주소를 추가합니다. 네이티브 Google 로그인을 쓰려면 `EXPO_PUBLIC_GOOGLE_*_CLIENT_ID`도 지정합니다.

- 매칭 엔진은 한 번에 하나만 실행합니다. DB 소유권 잠금으로 두 서버가 동시에 매칭하지 않게 막습니다. DB 연결이 끊겨 잠금을 잃으면 주문 접수를 닫고, 2초마다 잠금을 다시 얻을 때까지 스스로 복구합니다.
- `/api/health/ready`는 DB 연결, 매칭 소유권, 스케줄러 시작을 확인해 정상이면 200, 복구 중이면 503을 돌려줍니다.

- DB 연결 풀 사용량(`db.pool.*`)을 다른 시장 지표와 함께 1분마다 기록하고, 관리자 전용 `GET /api/market-metrics`로 봅니다.
- 웹 응답에는 Firebase Hosting이 CSP(운영 API·Google 로그인만 허용, 다른 사이트에 끼워 넣기 금지)와 `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` 헤더를 붙입니다.
- 운영 API 주소는 `endpoints.json` 한 곳에서 관리하고, CSP·감시 대상·앱 설정·문서가 같은 값인지 `tests/endpoints.test.ts`가 검사합니다.
- Dependabot이 매주 월요일 09:00(한국시간)에 웹·앱·백엔드·Actions 의존성의 마이너·패치 업데이트를 생태계별로 묶어 PR을 엽니다. 함께 올려야 하는 메이저 업데이트(TypeScript·ESLint, 앱 Firebase, Spring Boot)와 Expo·React Native 계열은 제외합니다.
- 서버의 논리 백업은 매일 한국시간 03:30에 만들고 7일 보관합니다.
- 무료 범위를 유지하려면 OCI 콘솔에서 DB 사양 변경, HeatWave 클러스터·고가용성·읽기 복제본 추가, 스토리지 자동 확장, 백업 보관 기간 연장을 하지 않아야 합니다. 비용이 생기면 바로 알 수 있도록 월 SG$1 예산을 만들어 두었습니다.

## 한계와 주의사항

- **모의 시장입니다.** 실제 돈·주식·게임 재화와 아무 관련이 없고, 투자 조언이 아닙니다. 탭 베팅·전광판에 쓰는 개인 지갑 돈도 가상 자금입니다.
- 종목 규모(이용자 수·시가총액)는 시뮬레이션용 입력값이며 실제 통계가 아닙니다.
- 뉴스 영향 점수는 키워드 규칙 기반이라 반어·문맥을 놓칠 수 있습니다. 공식 발표 수집은 상대 사이트 구조가 바뀌면 멈출 수 있습니다.
- 봇의 체결 목표는 목표일 뿐 체결량이나 유동성을 보장하지 않습니다. 거래 정지·자원 부족·DB 지연 중에는 호가가 비는 순간이 생길 수 있습니다.
- 접속자가 없는 동안에는 시장이 거의 멈춰 있습니다. 의도한 동작입니다.
- 무료 DB(1 ECPU)를 쓰기 때문에 동시 접속이 아주 많으면 응답이 느려질 수 있습니다.
- 커리어 설계 문서의 라이프 축(부동산 등)은 아직 구현하지 않았습니다.
