# GameStock

모바일 게임 데이터를 바탕으로 가상 종목을 거래하는 모의주식 서비스의 실행 가능한 초기 골격입니다.

현재 버전은 별도 데이터베이스 설정 없이 실행되는 **메모리 기반 데모**입니다. 종목 조회, 시장 이벤트 조회, 매수·매도, 보유 자산 계산이 실제로 동작합니다. 서버를 다시 시작하면 데모 데이터는 초기화됩니다.

## 실행 방법

PowerShell에서 프로젝트 폴더를 연 뒤 다음을 실행합니다.

프로젝트 루트의 `scripts\start.cmd`를 더블클릭하면 백엔드와 웹 화면이 창 없이 실행됩니다. 실행한 창을 닫아도 서버는 계속 유지됩니다.

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\start.ps1
```

PowerShell에서 직접 실행할 때는 위 명령을 사용하세요. 서버를 종료하려면 `scripts\stop.cmd`를 더블클릭하면 됩니다.

브라우저에서 [http://localhost:8080](http://localhost:8080)을 엽니다.

Java 17 이상이 설치되어 있어야 합니다. 실행 스크립트는 Microsoft OpenJDK 17을 사용합니다.

백엔드 실행 전에 프로젝트 루트의 `.env.example`을 복사해 `.env`를 만들고 `DB_PASSWORD`에 MySQL 비밀번호를 한 번 입력합니다. `.env`는 Git에 포함되지 않으며, 이후에는 비밀번호를 다시 입력하지 않아도 됩니다.

### 컴퓨터 재부팅 후 MySQL 설정

MySQL이 설치되어 있어도 서버 서비스가 실행 중이 아니면 백엔드가 `localhost:3306`에 연결하지 못합니다. 처음 한 번 관리자 권한 PowerShell에서 MySQL을 Windows 서비스로 등록하고 자동 시작으로 설정합니다.

```powershell
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqld.exe" `
	--install MySQL80 `
	--defaults-file="C:\ProgramData\MySQL\MySQL Server 8.0\my.ini"

Set-Service MySQL80 -StartupType Automatic
Start-Service MySQL80
```

정상 설정 여부는 다음 명령으로 확인할 수 있습니다.

```powershell
Get-Service MySQL80
```

`Status`가 `Running`이고 `StartType`이 `Automatic`이면 컴퓨터를 재부팅해도 MySQL이 자동으로 실행됩니다. 서비스 등록 후에는 `start.ps1`이 백엔드 실행 전에 MySQL 서비스 상태를 확인하고, 중지되어 있으면 자동으로 시작합니다.

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\start.ps1
```

MySQL과 백엔드의 로컬 연결에는 인터넷이 필요하지 않습니다. 단, RSS에서 최신 뉴스를 수집하려면 인터넷 연결이 필요합니다.

## 현재 구조

```text
backend/                  Spring Boot REST API 및 실시간 WebSocket 서버
frontend/                 웹 화면 (HTML, CSS, JavaScript)
mobile/                   Expo 기반 Android/iOS 앱
server/src/.../           기존 단독 실행 데모 서버
database/schema.sql       MySQL 전환용 초기 테이블 구조
scripts/run-backend.ps1   Spring Boot 서버 실행 스크립트
scripts/run.ps1           웹 화면용 기존 데모 서버 실행 스크립트
scripts/start.ps1         백엔드와 웹 화면을 한 번에 실행하는 시작 스크립트
scripts/start.cmd         실행 정책 우회 후 start.ps1을 호출하는 바로가기
scripts/stop.ps1          실행 중인 백엔드와 웹 화면 종료 스크립트
scripts/stop.cmd          stop.ps1을 호출하는 종료 바로가기
```

## 게임 뉴스 수집

백엔드는 `backend/src/main/resources/application.yml`에 설정된 종목별 RSS 피드를 서버 시작 후와 10분 간격으로 조회합니다. 새 뉴스는 `market_events` 테이블에 중복 없이 저장되고, 기존 웹 화면의 시장 이벤트 영역에 표시됩니다.

RSS 수집을 끄려면 실행 전에 다음 환경변수를 설정합니다.

```powershell
$env:GAMESTOCK_NEWS_ENABLED = "false"
```

피드 주소나 검색어를 바꾸려면 같은 `application.yml`의 `gamestock.news.feeds` 항목을 수정합니다. 형식은 `종목코드|RSS주소`입니다. 외부 RSS 서버가 응답하지 않아도 기존 시장 API와 거래 기능은 계속 작동합니다.

## 실제 주식시장 유사성 개선 계획

현재 GameStock은 화면, 호가창, 지정가 주문, 부분 체결, 사용자별 자산 계산을 갖춘 교육용 모의주식 서비스입니다. 실제 거래소의 동작에 더 가깝게 만들려면 아래 순서로 보완합니다.

### 0순위: 기타옵션

- [x] 첫 Google 로그인 후 닉네임 설정 화면 표시
- [x] 로그인 전에는 Google 로그인 버튼을, 로그인 후에는 메뉴 토글을 표시
- [x] 마이페이지에 닉네임·보유 종목·수량·평균 매입가·실시간 평가 손익 표시
- [x] 메뉴에서 봇을 제외한 사용자 투자 랭킹 조회

### 1순위: 주문·체결의 정확성

- [x] `trades` 체결 테이블을 추가해 하나의 주문에서 발생한 개별 체결을 별도로 저장
- [x] 시장가 주문도 현재가 즉시 체결이 아니라 매도·매수 호가를 순서대로 소진하며 체결
- [x] 지정가 매수 주문의 현금과 지정가 매도 주문의 주식을 주문 시점에 예약
- [x] 예약된 금액·수량을 체결·취소·만료 시 정확히 반환
- [x] 부분 체결마다 체결 수량, 체결 가격, 체결 시각을 기록
- [x] 주문 취소 API와 화면 추가 -> 체결 예약인 주문과 관련된 모든 화면은 마이페이지 안에 넣으면 될거같긴함
- [x] 가격·시간 우선 매칭에서 실제 체결을 유발한 주문과 대기 주문을 구분하고 체결 가격 규칙을 명확히 적용

### 2순위: 가격 형성 및 시장 규칙

- [x] 봇이 항상 매수·매도 주문을 교차시키지 않도록 현실적인 스프레드와 유동성 모델 적용
- [x] 사용자 주문량, 체결량, 호가 잔량을 가격 변동에 반영
- [x] 종목별 호가 단위(tick size)와 주문 가능 가격 검증
- [x] 거래 시간, 장 시작·마감, 장외 시간 주문 처리 추가 -> 24시간 계속 거래할수 있도록
- [ ] 일일 가격 제한폭, 거래 중단, 급등락 보호 규칙 추가 -> 하지마 도파민 터지는 방법은 저런거 없이 급등락이 완벽해야됨
- [x] 시장가 주문에 호가 부족·슬리피지 상황을 반영

※ 일일 가격 제한폭·거래 중단 규칙은 급등락을 제한하지 않기를 원한 요청에 따라 이번 범위에서 제외했습니다.

### 3순위: 계좌·결제 현실화

- [ ] 거래 수수료 계산
- [ ] 체결 후 결제 시점(T+N)과 미결제 현금·주식 구분
- [ ] 평균 매입가, 실현 손익, 평가 손익을 분리 계산
- [ ] 배당, 액면분할, 종목 변경 등 기업 이벤트 지원 -> 종목은 지금 3개에서 바뀔일이 없으니 안해도 ㄱㅊ을지도?
- [ ] 공매도·대주를 지원할 경우 담보와 강제청산 규칙 추가
- [ ] 잔고 변경과 체결 기록에 대한 감사 로그 추가

### 4순위: 시세·뉴스·운영 안정성

- [ ] 고정 초기값 대신 검증 가능한 외부 시세 또는 재현 가능한 시뮬레이션 데이터 사용
- [ ] 뉴스의 방향과 강도를 가격 변동 모델에 반영
- [ ] 체결 기반 OHLCV(시가·고가·저가·종가·거래량) 집계
- [ ] 단일 서버의 `synchronized` 처리 대신 다중 인스턴스에서도 순서를 보장하는 주문 큐 도입
- [ ] 중복 주문 방지, 요청 속도 제한, 장애 복구와 재처리 정책 추가
- [ ] Firebase 인증 외에 운영자 권한, 로그인 보호, 개인정보 보관 정책 정비

### 5순위: 급하진 않은데 있으면 재밌을만한거

1. 인생 리셋버튼 (각 구글 ID마다 한번씩만 가능하며, 마이페이지 맨 아래에서 버튼 눌러서 가능함 -> 이거 누르면 해당 유저의 모든 기록이 초기화되고 "투자가 이렇게 위험합니다"와 같은 문구를 띄워줌 -> 인생 리셋이 완료되면 마치 처음 가입하듯이 처음부터 플레이 가능 -> 단 한번만 이용할수 있다고 꼭 알림 띄워줘야됨)
2. 한강물 온도 표시하기 (실제로 한강물 온도 표시하는 사이트같은 곳에서 실시간 한강물 온도 가져와서 메뉴에 넣어두기)

위 항목을 모두 적용하면 실제 거래소를 복제하는 것은 아니지만, 현재의 게임형 가격 시뮬레이션에서 거래소형 모의투자 시스템으로 발전시킬 수 있습니다.
