# 씹덕주식

게임을 종목으로 상장시켜 모의 자금으로 거래하는 서비스다. 시세·뉴스·주문 데이터는
Spring Boot와 MySQL이 관리하고, 로그인은 Firebase Google 인증을 사용한다.
백엔드가 꺼진 개발 환경에서는 화면 확인을 위해 브라우저 모의 시세로 자동 대체된다.

## 실행

```bash
npm install
npm run dev        # http://localhost:5180
npm run typecheck
npm run build      # dist/ 생성
npm start          # dist/ 를 서빙하는 무의존성 Node 서버 (PORT)
```

### 로컬 백엔드 연결

1. MySQL을 실행하고 `database/schema.sql`을 적용한다.
2. 루트 `.env`에 DB와 Firebase Admin 설정을 둔다. 서비스 계정 JSON은
   `backend/secrets/firebase-admin.json`에 보관하며 Git에 커밋하지 않는다.
3. `scripts/run-backend.ps1`을 실행한다. Spring Boot API는 `http://localhost:8081`에서 열린다.
4. `.env.local`의 `VITE_API_BASE_URL=http://localhost:8081`을 확인하고 `npm run dev`를 실행한다.

웹 Firebase 설정은 `.env.local`의 `VITE_FIREBASE_*` 변수로 읽는다. 배포 시에는 같은 변수를
호스팅 서비스의 빌드 환경변수로 등록하고, 백엔드에는 `FIREBASE_SERVICE_ACCOUNT_JSON`,
`DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `GAMESTOCK_CORS_ORIGIN`을 별도 시크릿으로 등록한다.

### 배포

- **Railway 백엔드**: 서비스 루트를 `backend/`로 지정하고 `railway.json`이 해당
  `pom.xml`을 Maven으로 빌드한 뒤 `target/gamestock-backend-0.1.0.jar`를 실행한다.
  헬스체크 주소는 `/api/health`다.
- **Firebase Hosting 프론트엔드**: `npm run build` 결과인 `dist/`를 배포한다.
  프론트의 `VITE_API_BASE_URL`은 Railway 백엔드 공개 주소로 지정한다.
- **프론트엔드 자동 배포**: `.github/workflows/firebase-hosting.yml`이 `main` 브랜치 push마다
  타입체크·빌드 후 Firebase Hosting에 배포한다. GitHub 저장소 Settings → Secrets and variables → Actions에
  Firebase 관리자 서비스 계정 JSON 전체를 `FIREBASE_SERVICE_ACCOUNT` 시크릿으로 등록해야 한다.
- **정적 호스팅(ChatGPT Sites 등)**: `npm run build` 결과인 `dist/`를 그대로 올린다. 클라이언트 라우팅은
  `history.pushState` 기반이므로 서버에 SPA 폴백 설정이 필요하다.

## 화면

| 경로                       | 내용                                                                                          |
| -------------------------- | --------------------------------------------------------------------------------------------- |
| `/`                        | 자산 현황 · 전광판 · 거래량 상위 시세표 · 속보 (보유 종목이 있으면 내 보유 표 추가)           |
| `/market`, `/market/:code` | 전체 15종목. 정렬 가능한 시세표 + 필터(전체/상승/하락/관심) + 검색, 종목 상세(차트·주문·체결) |
| `/news`                    | 종목별 레일 + 날짜로 묶인 속보 피드. 각 소식은 발행 시점 대비 시세 반영률을 함께 보여 준다    |

## 구조

```
src/
  market/          시세 도메인과 서버 연동
    universe.ts    상장 종목, 호가 단위, 가격제한폭
    engine.ts      백엔드 연결 실패 시 사용하는 로컬 대체 엔진
    newsTemplates.ts  종목별 소재를 쓰는 소식 문구
    selectors.ts   자산 합계, 보유 종목, 정렬, 시세 반영률
    MarketProvider.tsx  Spring API 조회, Firebase 토큰 첨부, 주문 API
  lib/
    firebase.ts    Firebase Web SDK 초기화
    api.ts         Spring Boot 공통 API 호출기
  components/      표현 컴포넌트 (시세표, 전광판, 주문, 차트, 피드)
  pages/           화면 조합
  router.ts        pushState 기반 3개 경로 라우터 (의존성 없음)
  styles/          tokens → base → chrome/board/market/detail/news (CSS 레이어)
server/index.js    배포용 정적 서버
```

프론트는 2초마다 `/api/stocks`와 `/api/market-events`를 조회한다. 로그인 상태에서는 Firebase ID
토큰을 `Authorization: Bearer ...`로 첨부해 포트폴리오·주문·관심 종목 API를 호출한다.

## 설계 방향 계약

- **대상/장면**: 애니·게임을 종목처럼 사고파는 사람이 시세를 훑고 주문한다. 표면 모드는 Operate(작업 완수)이며,
  Persuade(설득)가 아니다. 그래서 히어로·카피·CTA를 두지 않는다.
- **시각 명제**: 증권사 로비의 **전광판과 인쇄된 시세표**. 흰 종이 위 1px 괘선이 구조를 만들고,
  색은 세 갈래뿐이다 — 상승 적색, 하락 청색, 전광판 암버 LED.
- **타입**: Pretendard(로컬 번들) 하나로 UI를 구성하고, 숫자는 tabular numerals를 쓴다.
  전광판 숫자만 모노스페이스로 LED 판독을 흉내 낸다.
- **시그니처**: 전광판 셀이 값이 바뀔 때만 번쩍이고, 번쩍임의 색이 상승/하락 방향을 알린다.
  자동 스크롤·반복 루프·펄스 점은 쓰지 않는다.
- **모션**: 피드백(틱 플래시, 주문 결과)만. 섹션 등장 애니메이션 없음.
  `prefers-reduced-motion`에서는 플래시를 아예 만들지 않고 값만 갱신한다.
- **안티고백**: ① 네온 크립토 대시보드 ② 히어로+피처 카드+통계 스트립 랜딩 ③ 벤토+라운드 카드+알약 필터 대시보드.
- **폐기한 것**: 마케팅 히어로, 영문 eyebrow(GAME STOCK EXCHANGE·MARKET EVENTS·DISCOVER), 카드 중첩,
  장식용 반투명 도형, 알약 필터, 중복된 "실시간" 문구.

## 검증 기록

- `npm run typecheck`, `npm run build` 통과. 빌드 산출물은 `dist/`.
- 정적 휴리스틱 감사(`frontend-apex` 스킬의 `audit_frontend.py`) 결과 0건.
  `outline: none` 2건과 9~10px 각인 배지는 코드에 사유를 남기고 예외 처리했다.
- 렌더 확인: 1440 / 900 / 390px에서 가로 오버플로 없음. 1080px 미만에서 2단→1단 전환,
  종목 상세가 목록 위로 이동, 전광판 열 수 축소, 터치 조작 34px 이상 확보.
- 공개 API 조회와 백엔드 연결 실패 시 대체 화면을 확인했다.
- 남은 작업: 실제 Google 로그인 후 주문·프로필 API의 브라우저 통합 테스트, Railway 배포 환경 점검.

### 서비스 요구사항

- 게임을 가상 종목으로 상장하고, 실제 게임 뉴스와 이용자 거래를 가격 형성에 반영한다.

- 실제 금융상품이 아닌 교육·관찰 목적의 가상 시장임을 화면에 명시한다.

## 외부 데이터 연동 요구사항

### 게임 뉴스

종목별 Google News RSS와 공식 X 공개 타임라인을 서버 시작 시와 10분마다 조회한다. RSS 기사는 `미디어 보도`, 게임별 공식 X 계정의 최신 글은 `업데이트 노트`로 저장한다. 종목명만 포함된 RSS 오탐은 제외하고, 공식 X 글은 계정 자체를 종목 경계로 삼는다. 화면에는 최신순으로 종목별 최대 5개와 전체 뉴스 10건을 표시하지만, 가격 계산에는 각 종목의 최신 관련 뉴스 최대 10건을 별도로 사용한다. 긍정·부정 영향도는 -10~+10 범위로 계산한다. 외부 피드 수집이 실패해도 기존 저장 뉴스와 시장 조회·거래는 계속 동작한다.

### 한강 수온

웹·모바일 메뉴는 [한강 수온 사이트](https://xn--939at9l4tgt7l6ps.com/ko)의 `선유` 측정소 행만 읽는다. 백엔드는 30분마다 조회하고 마지막 성공값을 캐시한다. 사이트가 실패하면 마지막 성공값을 유지하고, 값이 없으면 조회 불가로 표시한다.

## 졸업 프로젝트 보완 계획

현재 기능 구현은 완료되었으며, 졸업작품에서는 주식 연습이 아니라 **실제 게임 뉴스와 참여자 거래가 함께 가상의 게임주 가격을 만드는 과정을 구현·관찰하는 플랫폼**이라는 점을 중심으로 검증한다.

### 1. 문제 정의와 사용자 가치

- 프로젝트 정의: 실제 게임 뉴스를 바탕으로 사람과 봇이 거래하고, 뉴스 영향과 투자 행동이 최종 가상 게임주 가격을 결정하는 참여형 시장 시뮬레이션 플랫폼
- 핵심 흐름: `실제 게임 뉴스 수집 → 관련성·영향도 분석 → 사람·봇 매수·매도 → 호가·체결 → 최종 가상 주가와 변동 이유 표시`
- 해결 문제: 게임 뉴스가 투자자 심리와 게임 가치에 미치는 영향, 그리고 그 심리가 거래·가격으로 이어지는 과정을 한눈에 확인하기 어려움
- 핵심 사용자: 게임 이용자·관심자, 게임사·퍼블리셔, 게임산업 분석가·투자자
- 제공 가치: 뉴스·거래량·호가·가격을 한 흐름으로 확인하고, 특정 이슈에 대한 참여자 반응을 관찰
- 가격 원칙: 뉴스는 방향과 강도를 만들고, 사람·봇의 매수·매도·거래량·호가 불균형이 최종 체결 가격을 결정
- 현재 구현: 최근 24시간 뉴스·거래·호가 근거를 `/api/stocks/{stockCode}/price-drivers`로 계산하고 종목 화면에 설명. 자동 유동성은 내부 가격 형성에만 사용하며 별도 사용자처럼 노출하지 않음
- 졸업 프로젝트 연관성: 뉴스 감성 분석, 거래 매칭 엔진, 실시간 데이터 처리, 가격 형성 모델, 시각화를 하나의 서비스 흐름으로 통합
- 투자받을 이유: 게임산업의 기대와 반응을 관찰할 수 있는 특화 데이터를 만들고, 장기적으로 게임사·분석 조직용 대시보드·리포트·API로 확장
- 한계: 가상 주가는 실제 금융상품의 가격이나 수익을 보장하지 않으며, 사업성은 공개 게임 지표·실제 이용자 반응과의 추가 검증이 필요
- 성공 기준: 사용자가 뉴스→거래→가격 변화를 이해하고, 데이터 흐름이 일관되게 재현되며, 게임사·분석가 관점에서 시장 반응을 확인하는 데 유용한지 테스트·인터뷰로 검증

## 메모용

### 현재 고민

1. 왜 이 서비스에 투자해야 하는가? 게임사와 협업하지 않는 비공식 서비스만으로는 메리트가 부족할 수 있다. 협찬이 생기면 주간 수익 1·2·3위 사용자에게 소정의 보상을 제공하는 방안을 검토한다.
   - 대상 사용자는 서브컬처 게임을 좋아하면서 주식 경험도 해보고 싶은 사람으로 설정하고, 교육·관찰용 서비스로 방향을 잡는다.
2. 실제 사용자가 얻는 혜택은 무엇인가?
   - 실제 주식 투자 전에 손실을 줄이고 투자 판단을 공부할 수 있다.
   - 주간 랭킹 우수 사용자에게 프로필 꾸미기 아이템이나 칭호를 제공해 반복 이용 동기를 만든다.
3. 개별 기능은 구현되었지만 전체 서비스로서 목적과 반복 이용 이유가 부족할 수 있다.
   - 뉴스·거래·가격의 인과관계를 관찰하고 비교하는 졸업 프로젝트의 실험·교육 목적을 전면에 둔다.

### 우선적으로 추가하면 좋은 기능

1. 메인 화면에서 게임 뉴스와 가격 변동 이유를 함께 표시한다.
   - 뉴스 제목을 누르면 요약과 가격 영향 방향을 보여 주고, 상승은 빨간색·하락은 파란색으로 구분한다.
2. 1~2주 단위 시즌제와 시즌별 랭킹을 도입한다.
   - 시즌 종료 후 초기화 여부와 기존 자산 유지 여부를 결정한다.
3. 뉴스 확인·특정 수익률 달성·손실 제한 등 투자 미션을 추가한다.
   - 프로필과 랭킹에 표시되는 칭호를 보상으로 제공하는 방안을 검토한다.
4. 뉴스·거래량·시장 이벤트·봇 거래가 가격에 준 영향을 설명한다.
   - 복잡한 AI보다 뉴스 영향도·거래량 변화·호가 불균형을 근거로 한 규칙 기반 설명부터 확장한다.
5. 친구나 커뮤니티에 올릴 수 있는 투자 성적 공유 카드를 제공한다.
   - 포트폴리오와 시즌 성적을 이미지 카드로 저장·공유하는 기능을 검토한다.

## 실제 주식시장과 GameStock의 차이

GameStock은 실제 투자를 대체하는 서비스가 아니라, 게임 뉴스와 참여자 거래가 가상 게임주 가격에 미치는 영향을 관찰하는 시장 시뮬레이션이다. 따라서 주문·호가·체결 같은 시장 구조는 참고하지만, 법적·금융적 효력은 실제 주식시장과 다르다.

### 자산과 소유권

- 실제 주식시장: 실제 기업의 주식과 현금이 거래되며 법적 소유권이 발생한다.
- 내 프로젝트: 게임 종목을 기반으로 만든 가상 주식과 모의 현금만 사용하며 실제 소유권이 없다.

### 종목과 정보

- 실제 주식시장: 상장 기업의 공시, 재무제표, 산업·거시경제 정보가 가격에 반영된다.
- 내 프로젝트: 게임별 RSS 뉴스, 관련성 필터, 긍정·부정 영향도(-10~+10)를 중심으로 가격을 계산한다.

### 가격 형성

- 실제 주식시장: 실제 투자자·기관·시장조성자의 주문, 수급, 기업가치, 시장 심리가 함께 가격을 결정한다.
- 내 프로젝트: 사용자 주문, 봇 유동성, 호가 불균형, 체결 VWAP, 최근 뉴스 영향도를 규칙 기반으로 결합한다.

### 거래 참여자

- 실제 주식시장: 실명·본인확인 절차를 거친 다양한 투자자가 참여한다.
- 내 프로젝트: Firebase Google 로그인 사용자와 내부 자동매매 봇이 참여한다. 봇은 유동성 공급과 시장 흐름 재현을 위한 시뮬레이션 요소다.

### 거래 시간

- 실제 주식시장: 거래소별 정규장·시간외시장·휴장일·거래정지 규칙이 있다.
- 내 프로젝트: 실제 거래소와 다르게 24시간 운영예정

### 주문과 체결

- 실제 주식시장: 거래소의 가격·시간 우선 원칙, 시장가·지정가·부분 체결, 각종 주문 제한이 적용된다.
- 내 프로젝트: 시장가·지정가·부분 체결·주문 취소와 가격·시간 우선 매칭을 구현했지만, 거래소의 모든 주문 유형과 예외 규칙을 포함하지 않는다.

### 결제와 자금

- 실제 주식시장: 증권·현금의 결제 주기, 예수금, 담보, 증거금, 세금·수수료 규칙이 적용된다.
- 내 프로젝트: 체결 즉시 가상 현금과 보유 수량을 반영하며, 거래 수수료 부분은 실제 거래소를 따라가되 세금은 구현하지 않음

### 가격 제한과 안정장치

- 실제 주식시장: 거래소별 가격제한폭, 서킷브레이커, 변동성 완화장치, 시장감시가 적용된다.
- 내 프로젝트: 일반 가상 가격은 일일 제한폭을 사용하고, 봇은 더 좁은 내부 범위와 틱별 변동 제한을 적용한다. 실제 거래소의 안정장치를 모두 재현하지 않는다. (서킷브레이커 적용예정)

### 뉴스 반영

- 실제 주식시장: 공시·실적·정책·속보가 시장 참여자의 해석과 주문을 통해 간접적으로 가격에 반영된다.
- 내 프로젝트: 최근 관련 뉴스 10건과 24시간 누적 영향도를 규칙으로 계산하고, 뉴스의 직접 가격 영향과 거래 영향을 함께 반영한다.

### 사용자 기능

- 실제 주식시장: 투자 성과는 금융기관 계좌와 세금·수수료 내역을 기준으로 관리된다.
- 내 프로젝트: 랭킹, 마이페이지, 인생 리셋 등 학습·관찰·게임화를 위한 기능이 제공된다.

### 규제와 위험

- 실제 주식시장: 금융위원회·거래소·증권사의 규제, 투자자 보호, 이상거래 감시를 받는다.
- 내 프로젝트: 교육·연구용 가상 서비스이며 금융상품 판매, 투자 권유, 수익 보장을 하지 않는다.

### 차이를 해석하는 기준

- **비슷한 부분**: 호가창, 시장가·지정가 주문, 부분 체결, 체결 가격, 거래량, 뉴스에 따른 심리 변화 등 시장의 관찰 가능한 흐름을 단순화해 재현한다.
- **다른 부분**: 실제 기업의 가치·공시·거시경제·법규·실명 투자자·실제 자금이 없고, 뉴스와 봇의 움직임이 규칙 기반으로 설계되어 있다.
- **프로젝트의 목적**: 실제 수익률을 재현하는 것이 아니라 `게임 뉴스 → 참여자 반응 → 주문·체결 → 가상 가격`의 인과관계를 확인하고 설명하는 것이다.
- **이용 주의**: GameStock의 가격·랭킹·수익률은 실제 투자 판단이나 미래 수익을 의미하지 않는다.
